= Interop check: read kSTEP Part 21 with OpenCascade

`read_step_structure.cpp` reads a STEP file with OpenCascade's *typed* STEP model (no geometry
transfer) and prints the product structure it found: `PRODUCT`, `PRODUCT_DEFINITION`,
`NEXT_ASSEMBLY_USAGE_OCCURRENCE` (with relating/related ends), `APPROVAL`, the entity-type
histogram, the number of undefined entities and the OCCT model check (fails/warnings). It is an
independent reader for the product-structure half of the external-interop bar described in the
README; it does not prove geometry interop.

== Build and run

macOS (Homebrew):

[source,bash]
----
brew install opencascade
P="$(brew --prefix opencascade)"
c++ -std=c++17 -I"$P/include/opencascade" -L"$P/lib" -Wl,-rpath,"$P/lib" \
  scripts/interop/read_step_structure.cpp -o read_step_structure \
  -lTKDESTEP -lTKXSBase -lTKernel -lTKMath
./read_step_structure out.step
----

Linux (Debian/Ubuntu, see the README 'Building' section for the OCCT packages): same command with
`-I/usr/include/opencascade` and `-L/usr/lib/x86_64-linux-gnu`.

Produce a file with `kstep export script.kstep.kts --out out.step`.

== Result of 2026-10-22 (OpenCascade 7.9.3, macOS arm64)

`hello-assembly.step`: read status `RetDone`, 14 entities, none undefined, model check 0 fails and
0 warnings; products Housing (`HSG-001`), Bracket (`BRK-001`) and Screw (`SCR-001`) with their
definitions and both assembly usages resolved to the correct ends. A deliberately broken file is
rejected with a line-accurate error. Not covered: geometry, other CAD/PLM readers, full AP242
schema conformance, a lossless write-back round trip.

Two files written by the OCCT JNI bridge during the test run (`box-ap242.step` from

* `read_step_structure`: read status `RetDone`, 0 undefined entities, model check 0 fails and 0

== Result of 2026-10-22, `kstep export` with geometry (ADR-0027)

[source,bash]
----
kstep export kstep-tests/src/test/resources/export-box-20x30x40.kstep.kts --out box.step

----

* `read_step_structure`: both files `RetDone`, 0 undefined entities, model check 0 fails and 0
  warnings. `box.step`: 350 entities, 1 product, 1 `ProductDefinitionShape`, 1
  `AdvancedBrepShapeRepresentation`, 6 `AdvancedFace`. `assembly.step`: 696 entities, 2 products,
  1 assembly usage with both ends resolved, 2 shape representations, 12 `AdvancedFace`.
* FreeCAD 1.1.4 `Part.read('box.step')`: `Solid True 24000.0 6`.
* FreeCAD 1.1.4 on `assembly.step`: only the root product `Housing` arrives (one `Part::Feature`,

  the assembly, so an OCCT/FreeCAD reader has nothing to position it with.

== Result of 2026-10-22, placed assemblies (ADR-0028)

Tools: `dump_xcaf_tree.cpp` (reads through OCCT's XCAF and prints names, component flags,
locations, volumes and global bounding boxes; its `reference` mode writes an OCCT-authored
assembly to document OCCT's own entity convention), the extended `read_step_structure.cpp` (now
prints every `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION` with both representations and both axes),
`freecad_assembly_check.py` (FreeCAD headless, one mode per process) and
`verify-placed-assembly.sh` (all of it, writing only below `build/interop/`).

[source,bash]
----
P="$(brew --prefix opencascade)"
c++ -std=c++17 -I"$P/include/opencascade" -L"$P/lib" -Wl,-rpath,"$P/lib" \
  scripts/interop/dump_xcaf_tree.cpp -o build/interop/dump_xcaf_tree \
  -lTKDESTEP -lTKXCAF -lTKLCAF -lTKCAF -lTKCDF -lTKXSBase -lTKBRep -lTKTopAlgo -lTKPrim \
  -lTKG3d -lTKGeomBase -lTKMath -lTKernel -lTKService
build/interop/dump_xcaf_tree dump out.step
build/interop/dump_xcaf_tree reference ref.step
STEP_FILE=$PWD/out.step STEP_MODE=open freecadcmd scripts/interop/freecad_assembly_check.py
STEP_FILE=$PWD/out.step STEP_MODE=part freecadcmd scripts/interop/freecad_assembly_check.py
----

Fixture `export-placed-assembly.kstep.kts` (OpenCascade 7.9.3, FreeCAD 1.1.4, macOS arm64):

* `read_step_structure`: `RetDone`, 1094 entities, 0 undefined, model check 0 fails / 0 warnings;
  four `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION`, the bracket with axis (0,0,1), ref (0,1,0),
  location (30,5,10).
* XCAF: one free assembly `Baugruppe`, four components (the screw referenced twice), locations and
  global boxes as designed (bracket x 10..30, y 5..15, z 10..15), total volume 17384, box
  [0,40]x[0,40]x[0,22].
* FreeCAD `Import.open`: `App::Part` `Baugruppe` with four children `Gehaeuse`, `Halter`,
  `Schraube`, `Schraube001`, global boxes identical to the above. FreeCAD `Part.read`: 4 solids,
  volume 17384, box [0,40]x[0,40]x[0,22], valid.
* Necessity (files derived from the output): removing the four CDSR instances, or only the
  `PRODUCT_DEFINITION_SHAPE` on the usages, leaves XCAF with one empty free shape and no components.
* OCCT infers the direction: swapping `rep_1`/`rep_2` or `item_1`/`item_2` gave the same XCAF result.
  kSTEP follows OCCT's own writer (`rep_1` = component) for readers that do not infer.
* `export-placed-assembly-own-geometry.kstep.kts` (housing with its own box and a placed bracket):
  XCAF and FreeCAD keep both, the bracket as a component and the housing's own solid as an extra
  child named `SOLID` at the identity.

Not covered: other CAD/PLM readers, FreeCAD's own OCCT version differs from Homebrew's, assemblies
nested more than one level in a real reader (covered by unit tests only), scaling/mirroring (not
representable).

== Geometry operations (Welle J, ADR-0029)

`verify-geometry-operations.sh` exports the six Welle-J example scripts (plate with hole, union, common,
cut, revolved sleeve, chamfered prism), reads each file with `read_step_structure` and, when FreeCAD is
installed, prints shape type, validity, volume and face count. Manual, not part of CI. Result of
2026-10-22 (OCCT 7.9.3, macOS arm64): all six files read with status `RetDone`, 0 undefined entities,
model check 0 fails and 0 warnings; FreeCAD reports valid solids whose volumes and face counts equal the
closed-form values (see ADR-0029's Verification table).

== `kstep import` (ADR-0030, Welle K)

`verify-import.sh` exports the Welle I/J scripts, imports them again with `kstep import --output json` and
puts OCCT's own XCAF tree (`dump_xcaf_tree dump`) next to it. `dump_xcaf_tree nested <out.step>` writes an
OCCT-authored nested assembly (Hauptbaugruppe, Unterbaugruppe, Klotz) used as the reference for the
innermost-first placement order, and `freecad_make_box.py` has FreeCAD write a 10 x 20 x 30 box that kSTEP
reads back. All artefacts go to `build/interop/import/`. Result of 2026-10-22 (OCCT 7.9.3, FreeCAD 1.1.4, macOS
arm64): every volume, face count and bounding box agrees between hand calculation, `kstep import` and the XCAF
dump; the placed assembly agrees with FreeCAD's `Part.read` (4 solids, volume 17384, same bounding box); the
FreeCAD box reads back as volume 6000 with 6 faces.

`verify-mirror-scale.sh` (Welle P, ADR-0036) exports the six mirror/scale example scripts, reads each file with OCCT's typed
reader and FreeCAD and compares volume, face count, solid count and bounding box with the hand-computed values (6000,
24000, 48000, 750, 5974.2478 and 12000 with two solids); a deviation exits 1. `verify-mirror-scale.sh --spike` also builds
and runs `spike_mirror_scale_history.cpp`, which prints what `BRepBuilderAPI_Transform` reports for a mirror and a scale
(Modified/Generated/IsDeleted per edge, volume sign, STEP round trip, handedness of the mirrored surfaces; table in the
ADR). Both write only below `build/interop/mirror-scale/`.

`verify-face-ops.sh` (Welle Q, ADR-0037) exports the five shell / nearest example scripts, reads each file with OCCT's typed
reader and FreeCAD and compares volume, face count, solid count and bounding box with the hand-computed values (7152,
8912, 1448.2742, 9792 and 5948.4956); a deviation exits 1. `verify-face-ops.sh --spike` also builds (with `-lTKOffset`) and
runs `spike_shell_history.cpp`: signature and sign of `MakeThickSolid`, topology, edge identity, failures (offset 0, all
faces open, a hole closed by an outward wall), shell timings on 50 to 400-face prisms and point-to-edge / point-to-face
distance timings up to 9744 edges (table in the ADR). Both write only below `build/interop/face-ops/`.

`verify-derived-naming.sh` exports the three Welle-N2 example scripts (hole rim fillet at plate widths 40 and 60, union
section fillet), reads each file with OCCT's typed reader and FreeCAD and compares the volume and face count with the
hand-computed values 15491.650 / 8, 23491.650 / 8 and 7017.168 / 12. `verify-derived-naming.sh --spike` instead builds and
runs `spike_derived_history.cpp`, a standalone OCCT program that prints what `Generated()`, `Modified()` and `IsDeleted()`
report for fillet, chamfer and booleans (ADR-0034, table in the ADR). Both write only below `build/interop/derived-naming/`.
