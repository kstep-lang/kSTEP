= ADR-0094: Viewer Overlay Placement, Status Line Priority and Show in Script Position (Welle D3d-1)
:toc:

== Status

Accepted (Welle D3d-1). Scope: `kstep-desktop` packages `ui` and `status` and their tests. No new dependency, no error code, no migration (nothing is persisted), no worker or protocol change. The findings come from a hand test on macOS; nothing was checked on Windows or Linux.

NOTE: Since Welle SB-1 (ADR-0099) the status line lives in a status bar at the bottom of the window, and the MCP segments ("MCP", "MCP edit", "MCP files") are an indicator at its right end. Statements below about the toolbar and the MCP segment describe the state before that change.

== Context

A hand test of the desktop viewer showed three visual faults: the "Showing last good result" badge ran under the inspection panel in a narrow viewer; the status line cut its text in the middle ("2 hidden" and "unsaved changes" disappeared behind an ellipsis while the duration stayed); and the Show in Script button jumped down when its message appeared.

== Decision

D1. Badge placement. `ViewerOverlayLayout` (pure, no Compose) decides: without a panel the badge stays top left with the viewer width minus 2 x 12 dp. With a panel it needs 12 + 260 + 8 + 12 = 292 dp on the right, so it keeps top left while at least 140 dp remain (a viewer of 432 dp or more) and moves to the bottom left otherwise, with the full width minus the margins. The bottom is only the fallback because the panel never reaches it. The badge text wraps (at most 3 lines, no ellipsis); the dot stays 8 dp. The panel width and margin come from `ViewerOverlayLayout` as the single source.

D2. Status line segments. The run status is a list of whole segments with a priority. A character budget (`CHAR_DP` = 7.0 dp per character at 12 sp, deliberately wide: one segment too early is better than one cut) is derived from the available width. Segments are dropped in this order: duration, triangle count, then the medium ones (triangle warning, note, transparent count), then the high ones (knowledge label, transient notice, AI status); inside a class the last one goes first. Essential segments (state, hidden count, unsaved changes) are never dropped. There is no ellipsis marker; only an essential overflow can still end in a Compose ellipsis. The full text is the accessibility description and the tooltip as soon as a segment is left out. The preview origin ("Preview: saved file") stays its own text node outside the budget and is never cut.

D3. Show in Script position. The button sits directly below the title line in all three panels; the message is the last line of the panel. No height is reserved: without a message the panel is as high as before, with one it grows by the message row only.

== Alternatives not taken

* Badge always at the bottom (Rams): one rule less, but the badge would leave the place where the eye starts. Kept as fallback only.
* Duration dropped last (Raskin): the duration is the least actionable value of the line; hidden parts and unsaved changes change what the user sees or loses.

== Security

All texts were already made safe (`DisplayName.escaped`) before they reach the status line or the panels. `StatusSegments` works on plain strings and adds no raw data; tooltip and accessibility text show only these strings. No logging of content, no new input path.

== Consequences and open points

* `CHAR_DP` is an estimate, not a measurement; a font with wider glyphs could still make an essential run overflow into the ellipsis.
* The badge may sit at the bottom left in a very narrow viewer; since D3d-2 it stands above the controls hint (done, see Update).
* Not checked by hand on Windows and Linux.

== Update (D3d-2)

* *Badge and controls hint.* In the bottom-left fallback the badge is stacked above a reserve for the controls hint:
  `28 + 16 * L` dp (`L` = hint lines at the viewer width, greedy wrap at an estimated 7.0 dp per character; 2 lines at 410 dp
  = 60 dp, 3 lines at 300 dp = 76 dp). The reserve applies whether or not the hint is shown, so the badge never jumps (also
  not after the first orbit). Not chosen: hiding the hint (it is the only help for the controls and belongs to `kstep-viewer`)
  and measuring at run time (a measure-write-layout loop, flicker, extra recomposition). The reserve is generous; a headless
  scene test with the real hint proves it holds.
* *Status line.* The cause of the missing duration and triangles at 1200 px was weight sharing: the run status and the preview
  label both had `weight(1f, fill = false)`, so each got half and the unused part of the label was lost. `CHAR_DP = 7.0` stays
  an explicit estimate. The label now has no weight (natural width, never cut, ADR-0064); the run status gets the rest. D2
  (whole segments, no ellipsis inside a segment) is unchanged.
* *Known limit.* A viewer lower than about 400 dp with an inspection panel taller than 240 dp can still touch the badge in the
  fallback. Not solved, documented.
