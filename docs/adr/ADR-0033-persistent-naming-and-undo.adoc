= ADR-0033: Persistent naming of generated edges and undo/redo (Welle N)
:toc:

== Status

Accepted, implemented (kSTEP Welle N). Extends ADR-0015 (feature history), ADR-0031 (edge selection and tracking)
and ADR-0032 (sketches in the history).

== Context

ADR-0031 made edges addressable by geometry (`SelectEdges`) and by what they were before later operations
(`TrackedEdges`). Both still describe an edge by where it IS. After a parameter change a geometric predicate can
hit different edges, and an edge that an extrude or revolve GENERATED has no earlier geometry to select on. The
feature history also had no undo/redo: ADR-0015 and ADR-0031 listed both as open.

== Decision

=== Persistent naming: "generated by feature k from source s"

* A `GenerationSource` names a part of the PROFILE DEFINITION, not its geometry: `ProfileVertex(i)` /
  `ProfileEdge(i)` for a polygon profile, `RegionVertex(loop, segment)` / `RegionEdge(loop, segment)` for a region,
  `PointAt` / `SegmentAt` for resolvers that know coordinates, and the open `ExternalGenerationSource` (sketches:
  `SketchCorner(pointName)`, `SketchEdgeOf(from, to)`). The definition stays the same when a dimension changes
  (width 40 to 60), so the same logical edges are hit again.
* A vertex source has SIDE images (the edge swept from the vertex); an edge source has START and END images (its
  copies at the beginning and the end of the sweep; with a negative extrusion height START stays at z = 0).
* `GeneratedEdges(featureIndex, sources, role, expected, within)` is a new `EdgeReference` for
  `SelectedFilletFeature` / `SelectedChamferFeature`. `featureIndex` may equal the consumer's `baseIndex` (no
  step) or an earlier ancestor with exactly one operation path (`findPath`, shared with `TrackedEdges`; the
  edges are followed through `Modified` / `IsDeleted` history). `within` restricts the result with a Welle L
  selector on the base shape; `expected` checks the count.
* Strictness: a source without an image (a vertex on the axis of a full revolve), a tracking step that deletes or
  loses the edge, a wrong count, an unknown profile element, or a generator that cannot name edges (box, cylinder,
  translate, multi-body regions, an external feature without `supportsGeneratedNaming`) is an error, never a guess.
  `EdgeNamingException` carries the unresolved sources, the matched edges, the images each source has in the
  generator and all regular edges of the affected shape (the message lists at most 32). Scripts report it as
  `KSTEP-S-011`, the same family as edge-selection failures.

=== Resolution by coordinates

Kotlin turns every source into a coordinate query on the profile AS GIVEN (a vertex point, or start / end /
midpoint of a segment). The native side matches the queries against the vertices and edges of the profile face the
sweep started from (unique nearest vertex within `max(1e-6, vertex tolerance)`; an edge by both end vertices plus a
midpoint-on-edge check, which separates a line from an arc between the same points). That makes the orientation
normalisation of regions (outer counter-clockwise, holes clockwise) and the vertex replacement of `MakeWire`
irrelevant: no index arithmetic crosses the boundary. A query that matches nothing or is ambiguous is an
`IllegalArgumentException`.

=== One construction path

The plain and the named native entry points share one path (`buildSweep`): `nativeExtrudeProfile` is
`extrudeProfileImpl(..., nullptr, nullptr)`, `nativeExtrudeProfileNamed` is the same function with a query. The edge
indices of a named shape are therefore identical to the plain one (tested for profile, region and revolve);
otherwise `SelectEdges`, `TrackedEdges` and the index API would break silently.

=== Undo/redo: `FeatureHistory`

* Snapshot model: the undo and redo stacks hold immutable copies of the `FeatureSequence`; `Feature`s are value
  types and shared between snapshots. No `OcctShape` or native handle is ever held; shapes exist only for the
  lifetime of a `rebuild()` result. An `ExternalRootFeature` must not hold a native handle (`SketchFeature` holds
  parameters and a lambda only).
* Edits: `AddFeature`, `RemoveFeature`, `ReplaceFeature`, `MoveFeature` (and `update`). Add increments later
  indices at or above the position; remove is refused while a later feature refers to the feature
  (`REFERENCED_BY_LATER_FEATURE` with the dependents) and otherwise decrements; move applies the permutation to
  all indices (`remapIndices`, exhaustive over the sealed hierarchy including `TrackedEdges.sourceIndex` and
  `GeneratedEdges.featureIndex`) and refuses a forward reference (`ORDER_VIOLATION`); replace remaps nothing.
* Every new state passes `FeatureRebuilder.validateStructure` (now public; an empty sequence is valid there)
  before it enters the history, otherwise `INVALID_SEQUENCE` with the cause. A new edit clears the redo stack; past
  `limit` (1..10 000, default 100) the oldest undo entry is dropped; an edit that changes nothing is not recorded.
* The class is not thread-safe, and the history is NOT persisted: there is still no serialised feature format.

== Native bridge

New entry points `nativeExtrudeProfileNamed`, `nativeRevolveProfileNamed`, `nativeExtrudeRegionNamed`,
`nativeRevolveRegionNamed` and the test-only `nativeLiveShapeCount`. The generation map is encoded as
`[vCount, (n, idx...)*, sCount, (nStart, idx..., nEnd, idx...)*]` (at most 2 000 000 ints), decoded and validated by
`decodeGenerationMap` exactly like `decodeEdgeHistory`.

APIs used, all present in OCCT 7.9 (Homebrew 7.9.3 headers; Ubuntu 26.04 ships 7.9.2):
`BRepPrimAPI_MakePrism::Generated`, `::FirstShape(const TopoDS_Shape&)`, `::LastShape(const TopoDS_Shape&)`, the same
three on `BRepPrimAPI_MakeRevol`, `BRepBuilderAPI_MakeVertex` and `BRepExtrema_DistShapeShape` for the midpoint
check. *No new OCCT toolkit* (TKPrim, TKBRep, TKTopAlgo are linked already; the link line is unchanged). OCCT 7.8
is not tested and no 7.8 compatibility is claimed.

Invariants of ADR-0008: a freshly built sweep and its face share no TShape with a registered shape, so the map is
encoded without `g_mutex`; `publishHistory` runs before `registerShape`; nothing is registered on any error path;
`throwJava` and `registerShape` only outside the lock; full catch cascade. Degenerated edges are never reported as
images, so a vertex on the axis of a full revolve has an empty list that Kotlin turns into an error with candidates.

== Security

[cols="1,3"]
|===
| Area | Measure
| DoS | At most 1024 sources per call in Kotlin and 1024 vertices + 1024 segments natively; query arrays are length-,
finiteness- and range-checked natively (+/-1e7); the map payload is capped at 2 000 000 ints; `FeatureHistory.limit`
is at most 10 000 and snapshots are reference lists of at most 256 features; `MAX_SEQUENCE_LENGTH` stays 256.
Validation runs before any native call.
| Hostile input | `decodeGenerationMap` validates every count, length and index and throws `IllegalStateException`
(`GenerationMapDecodeTest`); the native entry points validate independently.
| Resource leaks | `NamedShape` is `AutoCloseable` and closed if decoding fails; `FeatureRebuilder` closes every built
shape on any error including `EdgeNamingException`; nothing is registered natively on an error path. A test measures
the native live-shape count before and after 100 failing builds and rebuilds (it must be equal).
| Concurrency | Unchanged: all registry access under `g_mutex`, no Java call under the lock.
| Logging | Messages contain indices, source descriptions (external ones at most 64 printable ASCII characters) and a
candidate list capped at 32; no secrets are involved.
| Crypto, SSRF | Not relevant to this wave (no network, no keys).
| Licence | No new dependency.
|===

== Not covered / follow-up waves

* Derived generators (fillet/chamfer boundary edges, boolean section edges, hole rim): implemented in ADR-0034
  (Welle N2); the remaining items are listed there.
* A persisted history or a serialised feature format.
* Naming of vertices and faces as a target; naming across edits that change the source topology (a point removed
  from a sketch).
* Box and cylinder as generators (they have no profile); naming through `TranslateFeature` as the generator (use
  `GeneratedEdges` on the feature before the translate).
* Multi-body regions (`ExtrudeRegionsFeature` / `RevolveRegionsFeature`, sketches with several separate contours)
  as generators: `nativeMakeCompound` copies the bodies, so their identity is lost; rejected with a clear message.
* OCCT 7.8 is not tested and not claimed.
* `ExternalRootFeature` gained two members with default bodies: source compatible, not binary compatible without
  `-Xjvm-default=all`.

== Consequences

* A part can be described as dimensioned sketch plus edges named by sketch point names; a parameter change keeps
  the same logical edges, and every failure is a structured error instead of a wrong solid.
* `rectangle(..., names = ...)` gives stable corner names; the default `p<index>` counts ALL points of the sketch
  so far, so a point inserted before the rectangle shifts the default names.
* Undo/redo costs nothing until the result is rebuilt.
