= Changelog
:toc:

All notable changes to kSTEP are documented here. The project follows
https://semver.org[Semantic Versioning]; while the major version is `0`, the API is unstable and
minor versions may contain breaking changes.

== Unreleased

=== Fixed

* Import: the new colour and layer mode made the OCCT transfer quadratic in the number of layer assignments and distinct
  colours (80k layers took 41 s under the global OCCT lock). A pre-transfer typed count now rejects more than 4096 layer
  assignments or 10000 colour definitions with `limit_exceeded` (`KSTEP-I-010`). The count also covers
  `SURFACE_STYLE_TRANSPARENT` and `SURFACE_STYLE_RENDERING_WITH_PROPERTIES` (10000 each), because OCCT's colour table is keyed
  by RGBA and distinct colour x transparency pairs were still quadratic (80k styled items took 67 s). These caps bound
  only the size of the colour table, not the work, because every `STYLED_ITEM` scans that table once (a full table plus
  300k styled items took 116 s). The count therefore also covers `STYLED_ITEM` / `OVER_RIDING_STYLED_ITEM` (at most
  200000) and bounds styled items x (colour definitions + rendering records) to 100000000. The style lists of
  `PRESENTATION_STYLE_ASSIGNMENT`, `SURFACE_SIDE_STYLE` and `STYLED_ITEM` are walked once per styled item too and could
  repeat one reference cheaply (10k styled items x 200k entries took 53 s); lists longer than 64 entries are rejected.
* Import: capped style lists still multiplied, because the colour reader walks styled item -> presentation style
  assignment -> surface side style -> fill area style as nested loops (four lists of 64 = 16.7M steps per styled item;
  100 such items in a 71 kB file took 15 s). The pre-transfer check now sums the weighted expansion cost of all styled
  items (memoised per entity, linear in the file) and rejects more than 10000000 with `limit_exceeded` (`KSTEP-I-010`);
  real files cost 1-3 per styled item. The fill styles of `FILL_AREA_STYLE` and the properties of
  `SURFACE_STYLE_RENDERING_WITH_PROPERTIES` are capped at 64 as well. New constant
  `StepImportLimits.MAX_STYLE_EXPANSION_WORK`.
* Import: an assembly "diamond" (each level using the same sub-assembly twice) has a small depth but 2^levels
  occurrences, and OCCT expanded it during the transfer before the Kotlin occurrence limit fired (28 levels, 56 kB: 69 s).
  The pre-transfer structure check now also counts the part occurrences after expansion on the usage graph and rejects
  more than 10000 (`StepImportLimits.MAX_EXPANDED_OCCURRENCES`, now also checked natively) with `limit_exceeded`
  (`KSTEP-I-010`) in well under a second.
* `kstep import` runs the import in a worker subprocess (ADR-0038). Four audit rounds kept finding new loops inside OCCT
  (a self-overriding `OVER_RIDING_STYLED_ITEM`, deep override chains and `MAPPED_ITEM` chains or cycles ended the process
  with exit 132 and no output at all; override chains, `MAPPED_ITEM` diamonds and shells repeating one face ran into or
  past the 60 s bound). The command now starts a second JVM (same runtime and class path, `-Xmx2g`, no JVM crash banner)
  and only supervises it: a regular end (exit 0 or 1 with one complete report) is passed through unchanged; a timeout
  (60 s, can only be lowered via `-Dkstep.import.timeoutMillis` / `KSTEP_IMPORT_TIMEOUT_MILLIS`; the worker and its
  children are killed), an OutOfMemoryError or an output overflow become `limit_exceeded` (`KSTEP-I-010`), a crash or an
  incomplete report becomes `read_failed` (`KSTEP-I-009`), as text or `--output json`. With `--output json` stdout is
  always exactly one JSON document. The previous in-process watchdog (`Runtime.halt`) printed a JVM fatal-error banner on
  stdout when it ended a native call; it now only bounds an orphaned worker, silently. Cost: one extra JVM start per
  import (about 0.08 s, see ADR-0038). A 100000-deep override chain still crashes OCCT's reader before any pre-scan
  runs; it now ends as one `read_failed` document instead of a silent exit 132. Library callers of `StepImporter` / `OcctKernel.readStep` still run in-process without a time
  or memory bound, and `kstep-mcp` has no import tool.
* Import: three more pre-transfer checks give the known worst cases a structured error in under a second (the worker is
  the guarantee, these are the fast path): `OVER_RIDING_STYLED_ITEM` chains deeper than 16 or cyclic, `MAPPED_ITEM`
  nesting deeper than 32 or cyclic and more than 10000 mapped-item expansions, and more than 250000 face references
  summed over all shells are rejected with `limit_exceeded` (`KSTEP-I-010`). New constants
  `StepImportLimits.MAX_OVERRIDE_DEPTH` and `MAX_MAPPED_ITEM_EXPANSIONS`.

=== Added

* Import of colours, layers and units (ADR-0038, Welle R). `kstep import` now reports the colour (sRGB, as written in the
  file) and layers of each part, each body of a multi-solid part and each styled face (`colour`, `layers`, `faceStyles`),
  the file's declared length unit (`sourceLengthUnit`: `declared`, `missing` or `mixed`, with the factor to mm) and a
  `presentation` summary; face numbers are OCCT's 0-based face order. New error `KSTEP-I-013` (`unit_unresolved`) for a
  length unit that cannot be resolved (for example a conversion factor of 0, for which OCCT otherwise returns a bounding
  box of 1e100). A new pre-transfer check bounds the product-structure depth (32) and detects cycles on the typed
  entities. `OcctKernel.surfaceTypeCounts` and the part key `surfaceTypes` count faces per surface kind (a B-spline face
  stays `FaceKind.OTHER`). New JNI entry points `nativeImportColors`, `nativeImportLayerRefs`, `nativeImportLayerNames`,
  `nativeImportStyleStats`, `nativeImportUnitInfo`, `nativeImportUnitNames`, `nativeShapeSurfaceTypeCounts`. Fixtures for
  styled, multi-body, inch, centimetre, metre, unit-less, unresolved-unit, structure-only and a FreeCAD B-spline loft,
  `scripts/interop/make_import_extras_fixtures.py` and `scripts/interop/verify-import-extras.sh`. Not included: instance
  colours and layers, edge colours, imported colours in `--render`, colour export.

* Face and vertex selection, `nearest(point)` and shell (ADR-0037, Welle Q). `Edges.nearest(point, within)`,
  `Faces.nearest` and `Vertices.nearest` pick the sub-shape(s) with the smallest GEOMETRIC distance to a point
  (`BRepExtrema_DistShapeShape`, ties are all returned); new `Faces.all()`, face `and`/`or`/`minus`, the
  `VertexSelector` family (`Vertices.all/atMax/atMin/nearest/ofEdge`), `Edges.atVertex`, `OcctKernel.selectFaces` /
  `selectVertices`, `OcctShape.vertices` (`VertexInfo`), `TopologySelectionException` as common base of the three
  selection failures (`KSTEP-S-011` in scripts; the constant keeps its name). One selector-tree validator now bounds
  depth 32 / 256 nodes over all cross-nested hierarchies, iteratively and before any hashing. `OcctKernel.shell` (face
  indices or a face selector, a positive thickness and `ShellDirection.INWARD`/`OUTWARD`), `shellWithHistory`, the
  script function `shell(...)` and `ShellFeature` with `SelectFaces` / `FaceIndices` in the feature history: an edge
  named before an INWARD shell is followed through it, an OUTWARD shell cannot be tracked through (refused with the
  reason). The wall must be thinner than half the smallest extent, the input at most 200 faces. Five new native entry
  points (`nativeShapeVertexInfo`, `nativeShapeVertexEdges`, `nativeShapeDistances`, `nativeShellShape`,
  `nativeShellShapeTracked`) and ONE new OCCT toolkit, `TKOffset` (the CI jobs check for it; on Ubuntu it is expected in
  `libocct-modeling-algorithms-dev`, proven only by the CI Linux job). Eight example scripts and
  `scripts/interop/verify-face-ops.sh` (with `--spike`). Not included: a pocket or hole from a face, draft and thickening
  (planned as Welle Q2), naming of the inner wall of a shell, `TrackedFaces`; see ADR-0037.
* Mirror and scale as shape operations (ADR-0036, Welle P). `OcctKernel.mirror(shape, plane)` and `scale(shape,
  factor, about)` return a mirrored or uniformly scaled COPY (also `mirrorWithHistory` / `scaleWithHistory`), new
  `MirrorPlane`, script-level `mirror(...)` / `scale(...)`, `MirrorFeature` / `ScaleFeature` in the feature history
  (persistent edge names set before the step are followed through it). Scale factor within [1e-6, 1e6]; solid or
  compound of solids as input, every result solid checked. Four new native entry points (`nativeMirrorShape`,
  `nativeScaleShape` and their `Tracked` variants), no new OCCT toolkit. `OcctKernel.compound(shapes)` combines
  separate bodies into one shape for one product definition (at most 32). Six example scripts plus
  `hello-scale-invalid`, and `scripts/interop/verify-mirror-scale.sh` (with `--spike`).
* Placement-aware render, preview and GLB (ADR-0035, Welle O). `kstep render`, `kstep asciidoc` and the preview
  pipeline now draw every instance of a placed assembly at its composed place (SVG, PNG and GLB; the GLB is one
  merged mesh). New public `AssemblyInstanceExpander` and `RigidPlacement.toGeometryPlacement()` in `kstep-shape`
  (limits: 4096 instances, 16384 visited nodes, depth 64); each distinct part is triangulated once. The JSON output
  gains `geometry.instanceCount` and `geometry.distinctShapeCount`, the text summary says `assembly: N instance(s)
  of M part(s)`, and an invalid placement degrades into a `placement_invalid` notice card. A model with several
  shapes but no assembly usage still previews shape 1 only, with a reworded warning.
* Sketch extensions (ADR-0032, Welle M). Circle and arc radii can be solver unknowns (`fixedRadius = false`);
  new sketch constraints `radius`, `diameter`, `equalRadius`, `tangent(line, circle)`, `tangent(circle, circle,
  internal)` and `angle(l1, l2, degrees)`; `SolvedSketch.radius(ref)`. New PlaneGCS constraint kinds 7-12 and
  scalar unknowns (`SketchScalar`, `RadiusConstraint`, `EqualScalarConstraint`, `PointOnCircleConstraint`,
  `TangentLineCircleConstraint`, `TangentCircleCircleConstraint`, `AngleConstraint`) behind the new native entry
  point `nativeSolveSystem` (at most 128 scalars).
* `SketchFeature` / `sketchFeature(...)`: a parametric sketch as a step of a feature history that re-solves on
  `FeatureRebuilder.rebuild`, through the new open interface `ExternalRootFeature` (and `ExternalFeatureException`).
* Several separate outer contours in one sketch become several bodies in one shape: `SolvedSketch.toRegions()`,
  `OcctKernel.extrudeRegions/revolveRegions`, `ExtrudeRegionsFeature`/`RevolveRegionsFeature`, native
  `nativeMakeCompound` (at most 32 bodies); STEP export writes them as one representation with several
  `MANIFOLD_SOLID_BREP`; `kstep import` reports them per body (`ImportedPart.bodies`, JSON field `bodies`).
* `OcctKernel.solidSummaries`, `groupLoopsIntoRegions`, `requireValidDisjoint`.
* Example scripts and `scripts/interop/verify-sketch-extensions.sh`.
* Persistent naming of generated edges (ADR-0033, Welle N). `GeneratedEdges(featureIndex, sources, role, expected,
  within)` addresses the edges an extrude or revolve generated from profile sources (`ProfileVertex`, `ProfileEdge`,
  `RegionVertex`, `RegionEdge`, `PointAt`, `SegmentAt`, and for sketches `SketchCorner` / `SketchEdgeOf` by point
  name), so a parameter change keeps hitting the same logical edges. Kernel API: `OcctKernel.extrudeProfileNamed`,
  `revolveProfileNamed`, `extrudeRegionNamed`, `revolveRegionNamed`, `generatedEdges`, and fillet/chamfer overloads
  on a `NamedShape`; `SolvedSketch.extrudeNamed/revolveNamed`; `EdgeNamingException` (`KSTEP-S-011` in scripts);
  `SketchBuilder.rectangle(..., names = ...)`. Four new native entry points, no new OCCT toolkit.
* Undo/redo: `FeatureHistory` with `AddFeature`, `RemoveFeature`, `ReplaceFeature`, `MoveFeature` over a
  `FeatureSequence` (immutable snapshots, index remapping, no shapes held), `FeatureHistoryException`.
* Example scripts for both and `scripts/interop/verify-persistent-naming.sh`.
* Naming of edges generated by derived features (ADR-0034, Welle N2). `GeneratedEdges` now also accepts a fillet,
  chamfer, boolean or hole as generator, with the new sources `BlendedEdges`, `OperandEdges(operand, selector)`,
  `OperandFaces(operand, faceSelector)`, `BooleanSection` and `HoleWall` and the new roles `BOUNDARY`, `SECTION`,
  `RIM_ENTRY`, `RIM_EXIT`. Kernel API: `OcctKernel.filletNamed`, `chamferNamed`, `booleanNamed`, `holeNamed`,
  `generatedEdges(DerivedNamedShape, ...)`, `DerivedNamedShape`, `MAX_DERIVED_QUERIES`. Strict like ADR-0033: a blind
  hole has no `RIM_EXIT`, a source without an image or a wrong count is an `EdgeNamingException` (`KSTEP-S-011`). Three
  new native entry points (`nativeFilletEdgesNamed`, `nativeChamferEdgesNamed`, `nativeBooleanOpNamed`), no new OCCT
  toolkit, OCCT 7.9 APIs only. The source/role/generator combinations are validated before any native call.
* Example scripts for the hole rim, a union section and an unresolved name, and
  `scripts/interop/verify-derived-naming.sh` (with `--spike` for the standalone OCCT history spike).

=== Changed

* `kstep import` reads with OCCT's colour and layer modes on (measured: no import-time difference on the placed-assembly
  fixture). The warning "ignored (not imported)" now names only `pmi`; `ignored.colours` and `ignored.layers` keep counting
  occurrences in the file. `DIMENSIONAL_EXPONENTS` (a unit entity) is no longer counted as PMI. A representation without
  any B-Rep is `no_content` (`KSTEP-I-011`) instead of a part with volume 0.

* The messages of `Placement.fromRowMajor3x4`, `Rotation.fromAxes`, the native `nativeTransformShape` and the
  exporter/preview refusal of two shapes on one product definition now name the way out (`mirror(...)`, `scale(...)`,
  `OcctKernel.compound(...)`); the old wording is kept as a prefix. A placement stays rigid.
* BREAKING (source): `GeneratedRole` gained the values `SECTION`, `BOUNDARY`, `RIM_ENTRY` and `RIM_EXIT`; an exhaustive
  `when` over `GeneratedRole` or `GenerationSource` in third-party code no longer compiles and needs the new
  branches. `GenerationMap` can carry images of derived sources (`images()` answers them by role).
* `SolveResult` gained a `scalars` field (default empty): source compatible, not binary compatible.
* Arcs now bind their end points with a point-on-circle constraint on the radius unknown instead of two distance
  constraints; labels and degrees of freedom are unchanged for fixed radii.
* BREAKING (source): `SolvedSketch.extrudeFeature/revolveFeature` now return `Feature` instead of
  `ExtrudeRegionFeature`/`RevolveRegionFeature`, callers using the concrete type must adapt; `toRegion()` fails with `INVALID_PROFILE` when the
  sketch has several separate outer contours (use `toRegions()`).
* `fillet`/`chamfer` (index, selector and history variants) refuse a shape with more than one solid with a clear
  message instead of failing inside OCCT.
* `FeatureRebuilder` closes all built shapes when an external feature fails with any runtime exception.
* `ExternalRootFeature` gained `supportsGeneratedNaming` and `buildNamedShape` with default bodies (source
  compatible, not binary compatible without `-Xjvm-default=all`); `FeatureRebuilder.validateStructure` is public.

* `kstep import` no longer fails for a part with more than 1024 solids: the per-body summary is omitted with a
  warning. Computing it for up to 1024 solids adds noticeable import time.
* Documentation: the README was split into focused documents under `docs/` (status, modules, building, releasing,
  usage, roadmap); the README itself is now a short entry point.

=== Fixed

* `kstep import`: a product-structure chain of thousands of levels (a few hundred kilobytes) could exhaust OCCT's
  recursive transfer and crash the JVM; depth and cycles are now checked on the typed entities before the transfer and end
  in `limit_exceeded` (`KSTEP-I-010`). A length unit with conversion factor 0 no longer yields geometry of size 1e100.
* Documentation: ADR-0031, ADR-0032 and ADR-0030 no longer claim OCCT 7.8 compatibility or a Linux CI on 7.8; the
  Linux CI uses 7.9.2 and 7.8 is not tested.

=== Notes

* Not covered: naming of edges generated by fillet/chamfer/boolean operations (next wave), naming for multi-body
  sketches, a persisted history, booleans with several bodies, tangency at arc ends, contours touching each other.
  The multi-body STEP layout is verified on OCCT 7.9.3 and by the CLI round-trip test on the Linux CI.

== 0.2.0 — 2026-10-22 (pre-release)

Third pre-release. It turns kSTEP from a product-structure tool into one that models, exports and reads
back geometry: `kstep export` writes product structure and placed assembly geometry, `kstep import` reads
STEP files (kSTEP, OCCT, FreeCAD) back, the OCCT bridge gains booleans, holes, revolve and chamfer, and a
sketch DSL with geometric edge selectors replaces opaque edge indices. As before, the GitHub release carries
a platform-independent JVM-only `kstep-cli-0.2.0.zip` (about 86 MB because it bundles the Kotlin compiler for
`*.kstep.kts` scripts) and a SHA-256 checksum, and nothing is published to Maven Central or Homebrew.

**Geometry, sketches and `kstep import` need the native bridges.** The zip is built without them, so those
features report a clear "unavailable" error there; build from source with a system OpenCascade (Linux
x86-64, or macOS arm64 via Homebrew) to use them. Interoperability is verified with OpenCascade-based readers
(OpenCascade's typed reader and FreeCAD), not yet with other CAD/PLM systems.

=== Added

* Sketch DSL and geometric edge selection (ADR-0031, Welle L). New module `kstep-sketch`
  (`dev.kstep.sketch`): `sketch { }` with points, lines, arcs, circles, `horizontal`/`vertical`/`distance`/`length`/
  `coincident`/`pointOnLine`/`parallel`/`perpendicular` and the sugar `rectangle`/`offset`; `Sketch.solve(
  requireFullyConstrained, maxIterations)` analyses degrees of freedom in plain Kotlin (redundant and
  contradictory constraints are named before the solver runs), solves through PlaneGCS and verifies the result;
  `SolvedSketch.toRegion()`/`extrude`/`revolve`/`extrudeFeature`/`revolveFeature`. Structured failures:
  `SketchException` with `SketchErrorKind`, `SketchSolverUnavailableException`. Circle/arc radii are fixed
  measures in this version. `kstep-geometry`: `Edges`/`Faces` selectors (`parallelTo`, `ofType`, `atMax`, `atMin`,
  `ofFace`, `longest`, `shortest`, `seams`, combined with `and`/`or`/`minus`), `Direction3`, `Point3`,
  `SelectionTolerance`, `EdgeSelection.resolve`, `EdgeSelectionException` (candidate list, `expected` count),
  `OcctKernel.selectEdges` and selector overloads of `fillet`/`chamfer` (the index API is unchanged),
  `OcctShape.edges`/`faces` (`EdgeInfo`/`FaceInfo`), `SelectedFilletFeature`/`SelectedChamferFeature` with
  `SelectEdges`/`TrackedEdges` (edges followed through later operations via OCCT's `Modified`/`IsDeleted`
  history: `filletWithHistory`, `chamferWithHistory`, `booleanWithHistory`, `translateWithHistory`,
  `holeWithHistory`, `EdgeHistory`, `TrackedShape`), `FeatureRebuildException.selectionFailure`, and regions
  with arcs, circles and holes (`ProfileRegion`, `OcctKernel.extrudeRegion`/`revolveRegion`,
  `ExtrudeRegionFeature`/`RevolveRegionFeature`). Scripts import `dev.kstep.geometry.select.*` and
  `dev.kstep.sketch.*` by default. New error codes `KSTEP-S-009` (`SKETCH_SOLVER_UNAVAILABLE`), `KSTEP-S-010`
  (`SKETCH_INVALID`) and `KSTEP-S-011` (`EDGE_SELECTION_FAILED`); `KStepScriptOutcome.RuntimeError` gained a
  `code` property (default `KSTEP-S-003`), and `--output json` reports it. Native: no new OCCT toolkit; new JNI
  functions `nativeShapeEdgeInfo`/`FaceInfo`/`FaceEdges`, `native*Tracked`, `nativeExtrudeRegion`/
  `nativeRevolveRegion`, each limit re-checked natively. Examples `export-sketch-plate-with-hole`,
  `export-box-fillet-z-edges`, `export-box-chamfer-top-edges`, `export-pocket-tracked-fillet`,
  `hello-sketch-unconstrained`; interop check `scripts/interop/verify-sketch-selection.sh`. Gate (2026-10-22, macOS
  arm64, OCCT 7.9.3): `clean check -Pkstep.occt.require=true -Pkstep.planegcs.require=true --no-build-cache`, 1590
  tests, 0 failures, 0 errors, 8 skipped (inverse-/property-gated); release-style build without natives: 0 failures,
  `verify-dist.sh` green.

* `kstep import <file.step>` (ADR-0030, Welle K): reads a STEP file (kSTEP, OCCT, FreeCAD) back through OCCT's
  XCAF reader and reports product structure, per-part volume/faces/bounding box, the expanded placed
  occurrences and totals, as text or `--output json`; `--validate` checks the AP242 V1 entities, `--render
  <out.svg|png|glb>` renders the imported geometry. Read-only apart from `--render`. Kotlin API:
  `dev.kstep.shape.importer.StepImporter`/`ImportedStepModel`/`StepImportValidation`,
  `OcctKernel.readStep`/`OcctStepDocument`, `OcctShape.boundingBox`, `BoundingBox`, `Placement.fromRowMajor3x4`
  and `rowMajor3x4`, `StepImportLimits`, `OcctImportLimitException`, `MeshPreview` (the SVG/PNG/GLB encoders
  of `PreviewRenderer`, output unchanged). Input hardening: no symbolic links, regular files only, 50 MB cap,
  extern-document references rejected, entity/node/part/face/occurrence/depth limits. Error codes
  `KSTEP-I-001` to `KSTEP-I-012`. Linux CI that requires OCCT now installs `libocct-ocaf-dev`. New interop
  tools: `dump_xcaf_tree nested`, `freecad_make_box.py`, `verify-import.sh`.

* `kstep export` merges the geometry of `shape(...)` registrations into the exported Part 21 file
  (ADR-0027). `Ap242ShapeExporter.export(header, roots, assignments)` / `exportToFile` accept all
  roots and several shapes (one per product definition, limits `MAX_SHAPES` and
  `MAX_TOTAL_GEOMETRY_INSTANCES`); the single-assignment overload is unchanged in output.
* `kstep export --require-geometry`: exit 1 and no file unless geometry was merged.
* Error codes `KSTEP-S-006` (`GEOMETRY_REQUIRED`), `KSTEP-S-007` (`GEOMETRY_UNAVAILABLE`) and
  `KSTEP-S-008` (`GEOMETRY_EXPORT_FAILED`); `--output json` reports a `geometry` object when shapes
  are involved.

* Placed assembly geometry (ADR-0028, Welle I): `place(usage, translation, rotation)` in the script
  DSL with `vec(...)`, `Rotation.about(...)`, `Rotation.fromAxes(...)`; the exporter writes a
  `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION` chain per geometric usage, so OCCT and FreeCAD import the
  components of an assembly (previously only the root). `kstep export --output json` reports
  `geometry.placementCount`/`usageCount`. New interop tools `dump_xcaf_tree.cpp`,
  `freecad_assembly_check.py`, `verify-placed-assembly.sh`. Gate (2026-10-22, macOS arm64, OCCT 7.9.3):
  `clean check -Pkstep.occt.require=true -Pkstep.planegcs.require=true --no-build-cache`, 1277 tests,
  0 failures, 0 errors, 6 skipped (the six known ones).

* Geometry operations on the OCCT bridge (ADR-0029, Welle J): `OcctKernel.makeCylinder`,
  `translate`/`transformed`, `union`/`cut`/`common`/`boolean` (single-solid results, face-limited operands),
  `hole`, `revolveProfile` (about X or Y, `RevolveAxis`) and `chamfer`; `OcctEmptyResultException` for empty
  boolean results; feature-history cases `CylinderFeature`, `RevolveFeature`, `TranslateFeature`,
  `BooleanFeature`, `HoleFeature`, `ChamferFeature`; example scripts `hello-plate-with-hole`,
  `export-plate-with-hole`, `export-boolean-{union,common,cut}`, `export-revolved-sleeve`,
  `export-chamfered-prism`, `hello-revolve`; `scripts/interop/verify-geometry-operations.sh`. Gate
  (2026-10-22, macOS arm64, OCCT 7.9.3): `clean check -Pkstep.occt.require=true
  -Pkstep.planegcs.require=true --no-build-cache --rerun-tasks`, 1333 tests, 0 failures, 0 errors, 6 skipped
  (the six known ones). The six exported STEP files read back as valid solids in OCCT's typed reader and
  FreeCAD with the closed-form volumes.

=== Changed

* `OcctGeometryException` is now `open` (parent of `OcctEmptyResultException`); `FilletFeature` implements the
  new `DerivedFeature` interface (constructor and `copy` unchanged); the native bridge links `-lTKBO`.
* CI/release workflows: the `apt-get` steps first download (resumable, three attempts with per-attempt
  timeouts) and then install offline, with a 40-minute step limit, after a slow mirror held the Linux OCCT job
  up twice on 2026-10-22 (its dev packages pull in about 450 MB). The Linux OCCT job also caches the downloaded
  packages with `actions/cache` (one entry per ISO week).
* The MCP server now reports the project version to clients (read from the jar manifest); it reported a
  hard-coded `0.1.0`, including in the 0.1.1 release.
* Geometry exports with assembly usages now carry an identity placement for usages without
  `place(...)`; the export text line gains `and K placed usage(s)`. (Render, preview and GLB honour
  placements since ADR-0035.)
* `kstep export` no longer prints "geometry merging is not wired into 'export' yet". A merge failure
  (unreachable or duplicate product definition, closed shape, OCCT error) fails with exit 1 instead
  of writing a structure-only file; native shape handles are closed on every path.
* The OCCT bridge detaches OCCT's default message printers while writing STEP, so OCCT's
  "Statistics on Transfer" banners no longer pollute stdout (and `--output json`).

== 0.1.1 — 2026-10-22 (pre-release)

Second pre-release. The GitHub release carries a platform-independent `kstep-cli-0.1.1.zip` (JVM only, without native bridges; about 86 MB because
it bundles the Kotlin compiler for `*.kstep.kts` scripts) and a SHA-256 checksum. Nothing is published to Maven Central or Homebrew. Geometry still needs a system OCCT
build (Linux x86-64 or, new, macOS arm64 via Homebrew).

=== Added

* macOS arm64 support for the OCCT and PlaneGCS native bridges (ADR-0026): platform-aware Gradle
  build (`clang++`, `.dylib`, Homebrew defaults, `-Pkstep.brew.prefix`), platform whitelist in the
  loaders (`detectPlatform`), unit tests for it, and a new CI job `build-native-macos`. Development
  use only: nothing is bundled, the dylib is unsigned, Intel Macs and Windows stay unsupported.
* Release pipeline (`.github/workflows/release.yml`, ADR-0025): pushing a `vX.Y.Z` tag builds
  `kstep-cli-X.Y.Z.zip` (without native bridges) with a SHA-256 checksum and creates or updates the
  GitHub release; pre-release automatically while the major version is 0. No Maven Central,
  Homebrew or signing yet.
* `scripts/release/` (tag validation, version check, checksum, release notes, distribution
  verification) and its self-test `test-release-scripts.sh`, which also runs in CI.
* `kstep export --validate`: opt-in population-level model validation (`USEDIN`, `INVERSE`,
  `UNIQUE`, acyclic usages) before the Part 21 file is written. Findings give exit code 1 and no
  file; if no verdict can be reached (limits, unsupported construct) it fails closed with the new
  code `KSTEP-S-005`. Text and `--output json` output, see ADR-0024. Default off, output without the
  flag is unchanged.
* `KStepModel.validateModel()` in `kstep-script` (`ModelValidationOutcome.Checked` /
  `Unavailable`).

== 0.1.0 — 2026-10-19 (pre-release)

First tagged release. It is a *pre-release*: no artifacts are published (Maven Central, etc.), and
the native geometry bridges need system libraries (OpenCascade for the OCCT modules, Eigen headers
for PlaneGCS) and are only verified on Linux x86-64. CI runs on Linux only; the semantic core was
additionally built and tested locally on macOS (geometry tests skipped there). Build from source,
see link:docs/building.adoc[Building].

=== Semantic core (ISO 10303 AP242)

* EXPRESS parser (ANTLR4, `Express.g4`) and a semantic model with Kotlin code generation, verified
  against an excerpt of the real AP242 schema, now sixteen entities
  (`product_definition_occurrence` and the `name`/`description`/`id` attribute entities included).
* Code generation resolves transitive `TYPE` alias chains (cycle- and depth-guarded),
  `ENUMERATION OF (...)` as Kotlin enum classes and closed `SELECT` types as sealed interfaces
  (ADR-0020). `EXTENSIBLE` and `BASED_ON` types are rejected loudly. Only types reachable from the
  emitted entities are generated.
* `SUBTYPE OF` inheritance flattening; `kstep-core` is an ergonomic validating layer over the
  generated types (ADR-0004).
* `DERIVE` attributes as computed properties on generated types (ADR-0021); `get_name_value`,
  `get_description_value` and `get_id_value` intrinsics and the population derives (ADR-0023).
* `WHERE`-rule evaluation including `USEDIN`/`SIZEOF`, `INVERSE` evaluation over a
  reverse-reference index, `UNIQUE` rules `UR1`/`UR2` and the acyclic `WR1` check for assemblies,
  all with size and depth limits (ADR-0022, ADR-0023). Structured violations with stable
  `KSTEP-*` codes; `Ap242ModelValidator` for whole-model checks (opt-in, not yet part of
  `kstep export`).
* Mandatory-attribute presence enforcement (`KSTEP-M-001`, `KSTEP-M-002`).

=== STEP Part 21 and tooling

* STEP Part 21 writer and reader (`kstep-step21`), including tolerant reading and value grammar.
* `*.kstep.kts` scripting host and the `kstep export` CLI command.
* `kstep render` headless preview (SVG, PNG, text and self-contained glTF/GLB).
* `kstep asciidoc`: pre-processing of `kstep` blocks in AsciiDoc documents (ADR-0019).
* MCP server (`kstep mcp`) exposing the entity builders, Part 21 export and `validate_model` as
  LLM tools with structured validation feedback.

=== Geometry and viewer (native bridges; Linux x86-64 verified)

* OpenCascade JNI bridge: boxes, extrusion and fillet, AP242 shape assignment, parametric feature
  history (foundation), triangulation.
* PlaneGCS 2D constraint solver bridge: coincidence, distance, horizontal/vertical, point-on-line,
  parallel and perpendicular.
* Interactive Compose Desktop viewer: orbit, zoom, pan, multi-shape scenes, per-part colors and
  smooth per-vertex normals (ADR-0018).

=== Known limitations

* No published artifacts; build from source (JDK 21).
* Part 21 output is verified by self-round-trip only. Interoperability with external CAD/PLM tools
  (for example FreeCAD) has not been validated; a fixture for the manual check lives in
  `kstep-tests`. Update (0.1.1): FreeCAD 1.x reads the files without error (0 objects, no
  geometry is written) and an OpenCascade typed reader resolves the product structure; geometry
  and other tools remain unverified.
* `kstep export` and the script host do not run model-level validation yet; an assembly cycle
  is not detected on export (exit code 0). Update (0.1.1): `kstep export --validate` now
  does this opt-in; without the flag a cycle is still exported.
* `QUERY` and general EXPRESS functions are not evaluated; `INVERSE`/`USEDIN` roles over entities
  that are not modelled follow the assumptions documented in ADR-0022/0023.
* The AP242 schema is a vendored excerpt, not the full standard.
* The LLM benchmark is deferred to a later version.
