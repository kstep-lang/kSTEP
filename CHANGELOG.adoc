= Changelog
:toc:

All notable changes to kSTEP are documented here. The project follows
https://semver.org[Semantic Versioning]; while the major version is `0`, the API is unstable and
minor versions may contain breaking changes.

== Unreleased

=== Added

* kSTEP Desktop: six MCP tools that change the app (Welle MCP-3, ADR-0097), behind a second switch "Allow agents to make changes"
  in View > MCP Server... (off by default, stored as `allowActions` in `mcp.json`, checked at every call): `kstep_desktop_set_script`,
  `kstep_desktop_replace_in_script` (both need the `expectedRevision` from `get_script`; one undo step of their own; the file is
  never saved), `kstep_desktop_run` (like the menu, optionally waits), `kstep_desktop_select`, `kstep_desktop_set_visibility` and
  `kstep_desktop_show_in_script`. At most 20 calls per second, one run per second, one waiting call at a time. Agent text is checked
  (1 MiB, no control or bidi characters). The status line shows "MCP edit" while changes are allowed and a short notice after an
  agent edit or run. New fixed codes `ACTIONS_DISABLED`, `STALE_REVISION`, `NOT_A_SCRIPT`, `DRAFT_OFFER_OPEN`, `TEXT_TOO_LARGE`,
  `INVALID_TEXT`, `NOT_FOUND`, `AMBIGUOUS`, `RATE_LIMITED`, `BUFFER_NOT_RUN`. With "Preview Unsaved Changes" on, an agent edit starts
  the automatic run like typing. Only built and unit tested on macOS; not yet tried by hand with a real agent.
* kSTEP Desktop: six more read-only MCP tools (Welle MCP-2, ADR-0096): `kstep_desktop_get_errors`, `kstep_desktop_get_parts`,
  `kstep_desktop_get_assembly_tree`, `kstep_desktop_get_selection`, `kstep_desktop_get_view` and `kstep_desktop_find_in_script`
  (the same safe search as the find bar, with a time limit). They read an extended snapshot that the window publishes (errors,
  parts, tree, selection without hover, visibility, settings), so the window never waits for an agent and one call sees one
  consistent picture. Every answer has `snapshotRevision` (also `kstep_desktop_get_status` and `kstep_desktop_get_script`).
  Answers of the list tools are at most 1 MiB and say `truncated`; texts from scripts and workers are cleaned. New fixed codes
  `INVALID_ARGUMENTS`, `INVALID_PATTERN` and `SEARCH_TIMEOUT`. Only built and unit tested on macOS; not yet tried by hand with a
  real agent.
* kSTEP Desktop: a built-in MCP server, read only (Welle MCP-1, ADR-0095). View > MCP Server... opens a dialog with a switch
  (off by default), the port (7391, the next nine are tried when it is busy), the command preview and the buttons Copy Command,
  Copy Token and Regenerate Token. The server listens on 127.0.0.1 only and checks method, path, Host, Origin and a bearer token
  (kept in `mcp-token`, mode 0600) before it reads a request body; bodies are limited to 1 MiB. Two tools:
  `kstep_desktop_get_status` and `kstep_desktop_get_script`. The status line shows "MCP" while the server runs and lights up for
  a moment on an authenticated call. New error codes `KSTEP-D-050` (no free port), `KSTEP-D-051` (token not stored) and
  `KSTEP-D-052` (settings not saved); new files `mcp.json` and `mcp-token` in the config folder; `jdk.httpserver` added to the
  runtime of the packaged app. Only built and unit tested on macOS; not yet tried by hand with a real agent, and not on Windows or
  Linux.
* kSTEP Desktop: Help menu and shortcut list fixes from a hand test (Welle D3d-3, ADR-0076 update). About is now in the Help
  menu on every system, as the last entry; on macOS the application menu keeps a second About entry that opens the same
  dialog (the `aboutInAppMenu` switch is gone). The Keyboard Shortcuts dialog has a visible scroll bar, a width between 280 and
  420 dp and a height that follows the window (160 to 480 dp), so the lower groups and Close are reachable in a small window;
  long labels no longer run into the keys, and Redo shows its two keys as "A / B". Soft Wrap and Preview Unsaved Changes stay
  out of the list on purpose (no key). New tests check that every action with a key has exactly one row. No new dependency, no
  error code, no protocol change. Only built and unit tested; the look is not hand-tested yet.
* kSTEP Desktop: three visual fixes from a hand test (Welle D3d-1, ADR-0094). The "Showing last good result" badge no longer
  runs under the inspection panel: it stays top left while 140 dp remain next to the panel (viewer of 432 dp or more), otherwise
  it moves to the bottom left, and its text wraps. The run status in the toolbar is made of whole segments; when it is too
  narrow, duration and triangle count go first, then medium and high segments, while the state, the hidden count and
  "unsaved changes" stay; the full text is the tooltip and the accessibility text. Show in Script sits right below the title in
  all inspection panels and its message is the last line, so the button no longer jumps. No new dependency, no error code, no
  protocol change. Only observed on macOS, not verified on Windows or Linux.
* kSTEP Desktop: selected parts get an outline (Welle D3c-3, ADR-0093). The silhouette of the selected parts is drawn in the
  accent colour with a thin halo in the surface colour; the fill tint of a selected part is lighter while the outline is shown
  (0.30 instead of 0.45). The outline is seen through other parts and through transparent ones (x-ray); a hidden part has none.
  A selection of more than 40 000 triangles, or one with more than 16 384 open edges, keeps the plain tint (no outline, no
  message). Hover still only tints. Picking stays exact and unchanged; the new `PickIndexScalingTest` measures how many triangle
  tests a pick costs at the load limit and beyond, and no BVH was built (ADR-0093). `CanvasHighlight` gained `outlineSelectT`
  and `haloRgb` with defaults, so existing callers compile. No new dependency, no error code, no protocol change. Not checked
  by hand on every platform.
* kSTEP Desktop: multi-selection and a part context menu (Welle D3c-2, ADR-0092). Cmd+click (macOS) or Ctrl+click (Windows,
  Linux) adds or removes a part, Shift+click in the assembly tree selects the visible part rows between the anchor and the
  click, at most 1000 parts (a longer selection is cut and says so). The secondary button, Ctrl+click on macOS, the Menu key
  and Shift+F10 open a menu: Show in Script, Hide, Isolate (others transparent), Show All, Copy Name(s), Select Children;
  an entry that cannot work stays visible, can be reached with the arrow keys and shows why. Copy writes the names (control
  characters made visible) only on that action. A multi-selection has its own panel (count, triangles, common size, no mass).
  Viewer: `CanvasPicking` gained default methods only; the canvas now also starts the gesture on a secondary or middle press, so
  right-drag orbit and middle-drag pan work in the picking path. No new error code, no new dependency, no protocol change,
  `layout.json` unchanged. Not checked by hand on every platform.

* kSTEP Desktop: Show in Script selects the name, or marks the call line (Welle D3c-1, ADR-0091). The render worker now reports
  the script line of the `shape(...)`/`place(...)` call behind each part (`sourceLine`, desktop worker only; the public
  `kstep render --output json` is unchanged). Show in Script selects the name on that line, else the unique name literal, else
  the whole line with the message "Marked the line where this part is added; its name is defined elsewhere."; two parts of one
  name lead to their own lines. A line is trusted only against exactly the text that was evaluated; otherwise the name search of
  ADR-0068 answers as before. Line only, no column; the line of the call, not of the name definition. No new error code, no new
  dependency, no protocol change, `layout.json` unchanged. Not checked by hand in the window.

* kSTEP Desktop: regular-expression search, whole word and group references in Replace (Welle D2c-4c, ADR-0090). The find bar
  has the switches `Aa`, `\b` (whole word) and `.*` (regex). The regex is a non-backtracking subset (a Pike VM, so no pattern
  can freeze the window): literals, `.`, classes, `^ $ \b \B`, groups, `|` and greedy quantifiers; back-references,
  look-around and lazy quantifiers are refused with a short message. Every limit is a count, not a clock (pattern 256
  characters, repeat 100, program 2,000 instructions, text 1 MiB, 10,000 matches, 50 million steps). Replace knows `$0`..`$9`
  and `$$` with regex on; search and replace run off the UI thread. No new error code, no new dependency, `layout.json`
  unchanged. Not checked by hand in the window.

* kSTEP Desktop: DSL names in the editor come from a completeness-tested list (Welle D2c-4b, ADR-0089). `styleFaces`,
  `styleEdges`, `styleInstance`, `inputFile` and `readInput` are now coloured; a test fails when a public script function is
  missing from the list; the incremental tokenizer resets itself when the name set changes. No new error code, no new
  dependency, `layout.json` unchanged. Not checked by hand in the window.

* kSTEP Desktop: incremental syntax colouring (Welle D2c-4a, ADR-0088). The editor no longer tokenizes the whole script on
  every change: the tokenizer is a resumable state machine and restarts at the line of the change until its state at a line
  start agrees with the stored one again; a typed character in a 1 MiB script scans about 80 characters instead of about a
  million. The result is identical to a full scan (property-tested against a frozen copy of the old tokenizer and against
  full scans after thousands of random edits); above 1 MiB, or if the proof ever fails, it falls back to a full scan. No
  visible change, no new dependency, no new error code, `layout.json` unchanged. Not checked by hand in the window.

* kSTEP Desktop: automatic preview of unsaved text (Welle D2c-3b, ADR-0087). *View > Preview Unsaved Changes* (check item, off
  by default, remembered in `layout.json` as the optional key `previewUnsaved`; the file stays version 1) previews the editor text
  while you type: 800 ms after the last edit, at most one run per 2 s, the last edit always runs. No automatic run while a run of
  the saved file is in progress, a draft offer is open, the window is not focused, nothing is open or the text is a note; a failed
  run keeps the last good picture. Text over 1 MiB is not run and reports `KSTEP-D-046` once. No new error code. Not checked by
  hand in the window.
* kSTEP Desktop: preview of unsaved text and keys for the banner (Welle D2c-3a, ADR-0086). *View > Run Unsaved*
  (`Shift+Ctrl/Cmd+R`) previews the editor text once, without saving: the text goes to a private folder (not the session folder)
  and the worker reads input files next to the real script. The status line names the picture (`Preview: saved file`,
  `unsaved buffer`, `unsaved buffer (older)`), the export still uses the saved file, a note previews only the saved file.
  *View > Banner Actions* (`Shift+Ctrl/Cmd+B`) puts the keyboard focus on the banner buttons (Tab/arrows, Enter/Space, Escape).
  New codes `KSTEP-D-046` to `KSTEP-D-049`. The warm worker request gets optional fields and now refuses unknown keys. Automatic
  preview while typing is not part of this wave (D2c-3b). Not checked by hand in the window.
* kSTEP Desktop: editor comfort (Welle D2c-2, ADR-0085). *View > Soft Wrap* (check item, off by default, remembered in
  `layout.json` as the optional key `softWrap`; the file stays version 1) wraps long lines; gutter, error bars, tooltips and
  "go to line" follow the wrapped positions. The bracket next to the caret and its partner are tinted (a lone bracket in the
  error tint); brackets in strings, comments and template delimiters are skipped, search limits 100,000 characters. Error marks
  in the gutter now move with the text and no longer turn hollow just because the buffer is dirty: they are hollow where the
  marked text itself was edited and disappear when it is deleted. Not checked by hand in the window.
* kSTEP Desktop: crash draft (Welle D2c-1, ADR-0084). An unsaved buffer is saved to a draft file in the config folder two seconds
  after the last change and on shutdown; after a crash the next open of that file offers Restore or Discard in a banner (Save is
  blocked until you choose). Drafts are deleted after a save, a Discard or Don't Save, limited to 1 MiB, 32 files and 30 days, and
  checked as untrusted input (links, owner, mode, size, path). New codes `KSTEP-D-042` to `KSTEP-D-045`.
* `kstep desktop [<script|note|folder>]` (Welle D1c-4, ADR-0083) starts the packaged macOS app and opens the path
  (`/usr/bin/open -n -a`, no shell, app from `/Applications`, `~/Applications` or `KSTEP_DESKTOP_APP`). Exit 1 if the app is
  not found or the system is not macOS. New codes `KSTEP-D-039`, `KSTEP-D-040`, `KSTEP-D-041`. macOS only; every call starts a
  new instance; the shell environment does not reach the app.
* kSTEP Desktop: Recent entries for single notes (ADR-0083). A note opened on its own (drop, start argument, Recent) is kept
  with its workspace folder; sidebar clicks inside a workspace are not. `recent.json` stays version 1 (additive `root`), the
  size limit is 128 KiB.

* kSTEP Desktop can be packaged as a macOS app and dmg (Welle D1c-3, ADR-0082): `./gradlew clean :kstep-desktop:packageDmg
  -Pkstep.native.exclude=true` builds `kstep-desktop/build/packaging/app/kSTEP.app` and `.../dmg/kSTEP-<version>.dmg` with
  plain jlink/jpackage, a bundled runtime and a separate worker folder. Unsigned (ad hoc), JVM-only (no native geometry
  bridge: scripts compile and are checked, geometry preview, export and import need a build from source), macOS arm64
  only, verified on one Mac. Not a release artefact. New code `KSTEP-D-038` (the packaged worker is missing or incomplete).

=== Changed

* kSTEP Desktop: the MCP tools now refuse arguments they do not know or that do not fit (`INVALID_ARGUMENTS`), also `kstep_desktop_get_status`
  and `kstep_desktop_get_script`; before, extra arguments were ignored (ADR-0096 D4). The hint of the MCP dialog lists what an agent can read.
* kSTEP Viewer: the controls hint is now the public composable `ViewerControlsHint` with the constant `VIEWER_CONTROLS_HINT`
  (same text, same drawing; Welle D3d-2, ADR-0094), so the desktop layout can reserve room for it.
* kSTEP Desktop: the first command-line argument is judged like a dropped path (ADR-0083): it can be a script, a note or a
  folder, a link or an unsupported type is refused with `KSTEP-D-033`, and a malformed path no longer crashes the start.
* `ImportWorkerLaunch.command` takes an optional `java` launcher (default unchanged); `WorkerSandbox.detect` likewise.
* kSTEP Desktop: warm render worker for the live preview (Welle D1c-2, ADR-0081). After a run the desktop starts the next
  worker in the background (spare mode, default): a run takes about 0.2 s instead of about 1.5 s (macOS arm64, measured),
  with the isolation of the cold path (one process per run). An opt-in reuse mode (about 0.15 s) keeps one process for
  up to N runs of the same script with best-effort isolation between them. Kill switch: `-Dkstep.desktop.warmWorker=off`
  or `KSTEP_DESKTOP_WARM_WORKER=off`. The first run after opening a file is not faster. Knowledge blocks, the AI check and
  export stay cold. Verified on macOS arm64; Linux sandbox and OCCT cases only after CI.
* `kstep render` no longer ends the process in its report code but through an internal exit hook; behaviour of the CLI is
  unchanged.
* The desktop worker JSON has an additional `dependencies` array (the input files a script read); the public
  `kstep render --output json` document is unchanged (Welle D1c-1, ADR-0080).

* kSTEP Desktop toolbar uses icon buttons with tooltips instead of text buttons (Welle T1, ADR-0079): Open, Export,
  Home, Tree, AI Panel, Show All, Isolate and Hide are 32 dp icon buttons that name themselves on hover; the opacity
  slider has a tooltip with the percentage instead of a text label. Tree and AI Panel show their on state with a
  tinted background.
* kSTEP Desktop: Export (menu, Cmd+E and toolbar) is disabled while the Convert dialog is open, so the two dialogs never
  overlap (follow-up to ADR-0078).
* kSTEP Desktop toolbar (Welle M3b, ADR-0076): Open Folder, Recent and Close Workspace are only in the File menu now;
  the folder chooser is titled "Open a folder of Markdown notes".
* kSTEP Desktop UI polish (Welle D9a, ADR-0064): the status line puts separators only between parts that are shown and
  shortens a long file name in the middle (extension kept) before it pushes the export line, the sandbox notice or the run
  status out; the export dialog shows the target as file name (always whole) and folder (shortened) with the full path as
  tooltip instead of cutting the end of the path; the line after an export stays until another file is shown, a newer run
  starts, a workspace opens or the next export dialog opens.

=== Fixed

* kSTEP Desktop: two leftovers of the D3d-1 hand test (Welle D3d-2, ADR-0094). In a narrow viewer the "last good result"
  badge at the bottom left no longer overlaps the controls hint: it stands above a reserve of 28 dp plus 16 dp per hint line.
  At 1200 px the run status no longer lost duration and triangles: the preview label next to it no longer takes half of the
  free room. Only observed on macOS.
* kSTEP Desktop: the Export tooltip now names the Convert dialog ("Close the convert dialog first") instead of
  "Open a script first" while that dialog is open; toolbar and File menu use the same rule.
* kSTEP Desktop: the off state of Tree and AI Panel no longer looks disabled.

=== Added

* Scripts can read files next to themselves with `inputFile("x")` and `readInput("x")` (Welle D1c-1, ADR-0080); the
  paths are recorded, refused with `KSTEP-S-016` (absolute, `..`, links, not a file, more than 64 files) or
  `KSTEP-S-017` (missing, too large). kSTEP Desktop watches exactly these files and re-renders when one changes or
  vanishes; an unusable list from the worker is ignored with `KSTEP-D-037`. Limits: only files read through these
  helpers are observed (raw `java.io` is not), paths are relative to the script folder (not the working directory),
  and inline scripts and knowledge-workspace blocks are not supported.

* kSTEP Desktop convert service (Welle M4a, ADR-0077): public `DesktopConvert` facade in kstep-cli over the same logic
  as `kstep convert`; desktop state machine with explicit replace confirmation; menu entry and dialog follow in M4b.
* kSTEP Desktop File > Convert... (Welle M4b, ADR-0078): menu entry, dialog and icon over the M4a service; Replace only
  after an explicit confirmation; the entry is disabled while the export dialog is open or a conversion runs.
* kSTEP Desktop Help menu (Welle M3b, ADR-0076): Keyboard Shortcuts (an overview built from the menu model) and
  About kSTEP Desktop (version, link to kstep.dev); on macOS About is in the application menu when the system handler
  is available.

* kSTEP Desktop Edit menu: Cut, Copy, Paste and Select All (Welle M3a, ADR-0075) with icons and native shortcuts
  (Cmd or Ctrl plus X, C, V, A). An entry is disabled with a reason in the status line when the editor is not the focus
  target ("Click into the editor first"), nothing is selected ("Select text first") or the clipboard is empty
  ("Clipboard is empty"). Paste normalises CRLF and lone CR to LF and refuses clipboard text over 4 MB with a notice;
  Cut and Paste are one undo step each.
* kSTEP Desktop Edit and View menus (Welle M2, ADR-0074): Undo, Redo, Find, Replace, Go to Line and Run Script, Home,
  Previous and Next Block, Toggle Transparent, Toggle Hidden, Isolate, Show All, Show AI Panel are menu entries with
  state (disabled with a reason in the status line), icons and native shortcuts; the single-key entries show their key
  in the text. The key branches the menu now owns were removed from the editor and the window; Redo (Cmd+Y,
  Ctrl+Shift+Z), F3 and Cmd or Ctrl+G stay as editor aliases. Run is disabled without an open file.
* kSTEP Desktop menu icons (Welle M1b, ADR-0073): the File menu entries (Open, Open Folder, Open Recent, Clear Recent,
  Close Workspace, Save, Export, Quit) show small stroke icons that follow the system appearance on macOS and the menu
  colour elsewhere; disabled entries are dimmed. Recent files themselves have no icon. Not looked at in the real window yet.
* kSTEP Desktop native File menu bar (Welle M1, ADR-0072): Open, Open Folder, Open Recent (with "No Recent Items" and
  Clear Recent), Close Workspace, Save, Export and, on Windows and Linux, Quit. Cmd+Q on macOS asks about unsaved changes
  like the close button. A disabled menu shortcut reports its reason in the status line. Ctrl+O/S/E on macOS and
  Meta+O/S/E on Windows and Linux no longer act.
* `kstep convert --recursive` (Welle D8d, ADR-0071): converts a whole folder tree (depth 8) and mirrors the sub-folders
  below `--out`. Links are never followed (reported as `symbolic_link`), hidden folders and an output folder inside the
  input are skipped (`hidden_dir`, `output_dir`), every folder must stay below the input folder (`KSTEP-C-013`),
  depth over 8 is `KSTEP-C-012`; the JSON report gets `"recursive":true` and `written[].target`, output without the switch
  is byte-identical to before. Created target folders are not removed if a later write fails (not transactional). Windows
  links and junctions are untested.
* Block attribute `{name=...}` (Welle D8d, ADR-0071): ```` ```kstep {name=bracket} ```` names a block; `convert --to kts`
  writes `<note>-bracket.kstep.kts` instead of `<note>-2.kstep.kts` (a single block keeps `<note>.kstep.kts`), the
  Desktop block header shows the name. Invalid, malformed or duplicate names are `KSTEP-C-014` / `KSTEP-C-015`; unknown keys
  (for example Pandoc style attributes) are warnings `KSTEP-C-016` (`warnings` in the JSON), so existing notes keep working.
  The name is not written back by `--to okf` and not put into the script.
* kSTEP Desktop export dialog (Welle D7d, ADR-0070): the running export shows a step line ("Step 2 of 4") and, while
  writing a file of 8 MiB or more, a real progress bar and percentage; the dialog remembers format, folder and the
  declared target per script (32 scripts, `export.json` version 2), and the script's export block keeps precedence.
* kSTEP Desktop AI panel (Welle D6d, ADR-0069): partial apply. A proposal with several changes shows one checkbox per
  change group; "Apply k of n changes" builds the chosen subset, checks it again in the worker sandbox and applies it
  atomically only if it compiles ("Apply anyway" if the geometry engine is missing or it does not compile, with the
  verdict shown). Without a sandbox the choice is not offered (`KSTEP-D-034`); if the editor changed during the check
  nothing is applied (`KSTEP-D-035`).
* kSTEP Desktop AI prompt history (ADR-0069): the last 50 prompts, arrow up/down in the prompt field and a list with
  "Clear history". Prompts only, stored as plain text in the config folder (mode 0600 where supported); a prompt that
  contains the API key in use is not stored.

* kSTEP Desktop selection leftovers (Welle D3b, ADR-0068): "Show in Script" in the part and group inspection panels and
  as a double click on a part in the assembly tree. It looks for the literal `"name"` in the editor buffer; exactly one
  hit moves the caret and scrolls there, several hits show a message with a Find action that opens the find bar, no hit
  or an unsearchable name shows a message. The button is disabled with a reason when there is no script, no name or a
  knowledge note is open. Name heuristic only: variables, templates and run-time names are not found.
* The viewer canvas no longer recomposes when the hover cursor changes (ADR-0068): the cursor is read in a small
  composable of its own, checked by a recomposition-count test.

* kSTEP Desktop editor leftovers (Welle D2b, ADR-0067): a click on an error-bar entry with a position marks its line in the
  editor until the text changes or Esc is pressed (an entry without a position is not clickable and says so); hover tooltips
  on the gutter marks (code, position, message; at most three errors, 120 characters per line); go to line (Cmd/Ctrl+L) with
  live validation; find and replace without regular expressions (Cmd/Ctrl+F; Cmd+Alt+F or Ctrl+H with the replace row;
  Enter, F3 and Cmd/Ctrl+G for the next match, with Shift backwards) with a case toggle, at most 256 characters to find,
  4096 to replace with, 10,000 matches, and a result that keeps the 1 MiB and 20,000-characters-per-line limits; "Replace
  all" is one undo step; the split between editor and viewer is remembered in `layout.json` (at most 1 KiB, untrusted when
  read). The crash-safe draft of an unsaved buffer moves to Welle D2c. The window itself (focus changes between the bar and
  the editor, input methods, shortcuts on Windows and Linux) was not exercised by hand.
* kSTEP Desktop remembers recently opened scripts and folders (Welle D1b, ADR-0066): a "Recent" menu in the toolbar and a
  list of up to five entries on the empty window, at most ten kept in `recent.json` (untrusted when read, no file access
  until an entry is clicked; a vanished entry or a link is removed with `KSTEP-D-032`). Scripts, notes and folders can be
  dropped on the window; the first usable item opens, the others are counted in the status line, anything else is refused
  with `KSTEP-D-033`. A note dropped from outside the open workspace opens its folder first. Watching dependent files is
  not part of this wave: the script layer reports no dependency list, so it moves to Welle D1c.
* `kstep export --target <step|glb|stl|3mf|name>` and `--all-targets` write the targets a script declares in its `export { }`
  block (Welle D7c, ADR-0065), with `--out-dir`, `--force` and `--tolerance` (STL/3MF). Targets and names are validated again,
  everything is produced before the first write, each file is written atomically through the writer of `kstep convert`, and an
  existing file is only replaced with `--force`. `kstep export` without these flags is unchanged. The release smoke test
  (`verify-dist.sh`) covers it.
* Declarative `export { }` block and remembered export folder (Welle D7b, ADR-0063): a script can declare up to four file names
  (`step`, `glb`, `stl`, `threeMf`, one per format) that the kSTEP Desktop export dialog suggests; names are validated strictly
  (no paths, control or direction characters, reserved device names, extension must match the format) and an invalid declaration
  is a script error. The desktop reads the names from its own worker result only (never from the public `kstep render` JSON,
  which is unchanged), treats them as hostile input and drops the whole list with a notice if anything is off. The dialog
  remembers the last format and folder between sessions. `KStepModel` gained a last field `exportTargets` (source compatible,
  not strictly binary compatible). Moved to D7c: export all names in one go, an own file picker, per-format options, a real
  progress percentage, `kstep export` bound to the block.
* Sandbox for your own scripts in kSTEP Desktop (Welle D6c, ADR-0062): live preview, export and knowledge-workspace blocks now
  run in `sandbox-exec` (macOS) or `bubblewrap` (Linux) with no network and write access only to their session folder; reading
  stays allowed. The system is probed once per program run; where the probe fails (Windows, Linux without a working
  `bubblewrap`) the flows run as before and the status line and the export dialog show "Script runs without sandbox", with the
  reason as a tooltip. A start failure after a successful probe is the new error `KSTEP-D-031`, without retry or fall-back.
  Behaviour change: a script that writes outside the session folder fails in the Desktop but not under `kstep render`.
  Linux user-flow sandbox: not yet confirmed in CI. Moved to D6d: kstep-mcp whitelist tools, more providers with an SSRF check,
  prompt history, Windows Credential Manager and AppContainer, new script from prompt, the `Inspect | AI` tab pair, a key broker,
  applying single hunks (the chosen subset must be checked again before applying), `SessionDirGuard` before writing the block
  file, JNI and further Mach services, TIOCSTI on macOS, read protection.
* `kstep convert` extensions (Welle D8c, ADR-0061): the input may be a folder (one level, no recursion, no links, hidden files skipped;
  `--to okf` converts every `*.kstep.kts`, `--to kts` every `*.md`; empty scripts and notes without a `kstep` block are skipped, any

=== Added

== 0.4.0 — 2026-11-12 (pre-release)

Fifth pre-release. It adds three more face-based shape operations (pocket or hole from a face, draft, thickening),
persistent names for the inner wall of an INWARD shell, transparency and edge colours in the STEP export and import, and
a hardened `kstep import` worker. Release 0.4.0 is the first release published to Maven Central (group `dev.kstep`,
twelve library modules); the jars contain no native libraries. As before, the GitHub release carries a
platform-independent JVM-only `kstep-cli-0.4.0.zip` (about 87 MB because it bundles the Kotlin compiler for
`*.kstep.kts` scripts) and a SHA-256 checksum; nothing is published to Homebrew.

**Geometry, sketches and `kstep import` need the native bridges.** Neither the zip nor the Maven Central jars contain
them, so those features report a clear "unavailable" error there; build the bridges from source with a system
OpenCascade (Linux x86-64, or macOS arm64 via Homebrew) to use them. Interoperability is verified with
OpenCascade-based readers (OpenCascade's own readers and FreeCAD), not yet with other CAD/PLM systems.

=== Added

* Maven Central publishing (ADR-0043): the twelve library modules `kstep-core`, `kstep-express`, `kstep-step21`,
  `kstep-script`, `kstep-shape`, `kstep-geometry`, `kstep-constraints`, `kstep-sketch`, `kstep-render`, `kstep-preview`,
  `kstep-mcp` and `kstep-asciidoc` are published as `dev.kstep:<module>`, signed, with sources jars and an empty javadoc
  jar. The jars contain no native libraries: `kstep-geometry` and `kstep-constraints` ship only the Kotlin API, and users
  build the bridges themselves and load them with `-Dkstep.occt.bridge.library` / `-Dkstep.planegcs.bridge.library` (absolute paths); the jars target JDK 21.
  `kstep-cli`, `kstep-viewer` and `kstep-tests` are not published. The release workflow gets a `maven-central` job that
  runs after the GitHub release, gated on four secrets and on the tag still pointing at the built commit, and idempotent
  (all twelve POMs are probed; a partial state fails closed). An allow-list (`publishedModules`) with the coverage check
  `verifyPublicationCoverage`, the fail-closed task `verifyNoNativeLibraries` and the release scripts
  `check-maven-central.sh`, `verify-maven-artifacts.sh` and `published-artifacts.txt`; `ci.yml` stages and verifies the
  Maven repository on every PR.
* Welle Q2 (ADR-0040): faces as the input of three more operations. `pocket(shape, face, profile, depth)` cuts a
  rectangle, circle or polygon (`PocketProfile`) into the one planar face a selector names, blind or through
  (`PocketDepth`); a hole is a circular pocket. A blind depth that would reach through the material under the profile
  (stepped body, existing cavity) is refused. The profile lives in a local coordinate system of the face (origin =
  centroid, `U` = +X projected into the face, `V` = N x U) and must lie strictly inside the face; an ambiguous
  selection is `KSTEP-S-011`, not a silent first pick. `draft(shape, faces, angleDegrees, NeutralPlane(origin,
  pullDirection))` tapers planar faces (`BRepOffsetAPI_DraftAngle`; a positive angle narrows the material along the pull
  direction). `thicken(shape, faces, distance)` pushes planar faces outward and extends their neighbours
  (`BRepOffset_MakeOffset`). Matching `OcctKernel` functions and the feature types `PocketFeature`, `DraftFeature` and
  `ThickenFeature`, which rebuild with undo/redo. A tracked edge is followed through a pocket; draft and thicken report
  no usable edge history, so tracking through them is refused with the reason.
* `scripts/interop/verify-face-ops-2.sh` (with `--spike` and `--baseline`) re-checks the six example exports with OCCT and
  FreeCAD and compares the pre-Q2 examples byte for byte with the previous commit.
* Welle T (ADR-0041): persistent names for the inner wall of an INWARD shell. New sources `ShellInnerEdges(selector)` and
  `ShellInnerFaces(selector)` with the new role `GeneratedRole.CAVITY` (appended at the end of the enum): the inner copy of
  the input edge, or the edges of the inner copy of the input face, that the selector names on the shell's INPUT. A
  `ShellFeature` with direction INWARD is now a generator for `GeneratedEdges`; `OcctKernel.shellNamed` and the JNI entry
  `nativeShellShapeNamed` read edge history and generation map from the same `MakeThickSolid` maker. Strict: an input edge
  that borders only opened faces, an opened face, an ambiguous or missing image ends in an `EdgeNamingException` with the
  candidates (`KSTEP-S-011`). An OUTWARD shell cannot name its inner wall (the generated copies are the new outer skin) and
  is refused before any native call. Unnamed shells are unchanged. Example: rounding the four inner vertical edges of a
  40x30x20 box shelled with a 2 mm wall gives V = 7167.451 and 15 faces, 9816.035 after the box becomes 30 high.
  `scripts/interop/verify-shell-inner-naming.sh` (with `--spike`) re-checks the exports with OCCT and FreeCAD.
  Source-incompatible for exhaustive `when` over `GeneratedRole` or `DerivedGenerationSource` in third-party code.
* Welle U (ADR-0042): transparency and edge colours in the STEP export. `StepColour` gets an opacity: `StepColour.rgba(r, g,
  b, a)`, `StepColour.hex("#RRGGBBAA")`, `StepColour.a` and `isOpaque`; an alpha outside 0..1 or not a number is
  `KSTEP-S-012`. A translucent part or face colour is written with `SURFACE_STYLE_TRANSPARENT(1 - a)` and read back by OCCT
  and by `kstep import`. New `styleEdges(pd, edgeSelector, colour, expected)` colours single edges (`CURVE_STYLE`, opaque
  only: a translucent edge colour is `KSTEP-S-012`; no match or wrong count `KSTEP-S-011`, a second colour `KSTEP-S-014`),
  with the types `EdgeStyle` and `ShapeStyle.edges`. `kstep import` reports `alpha` in every colour object (JSON; text only
  below 1.0), a new `edgeStyles` list per part and `edge N  colour (r, g, b)` lines. The writer entry `nativeWriteStepStyled`
  has two more arguments (edge indices and colours) and four-value colours; the allow-list of the style merge gets
  `SURFACE_STYLE_RENDERING_WITH_PROPERTIES`, `SURFACE_STYLE_TRANSPARENT`, `CURVE_STYLE` and
  `DRAUGHTING_PRE_DEFINED_CURVE_FONT`, with curve styles allowed only on edges and surface styles only on solids and faces.
  An opaque colour is written by the unchanged code path, so every file without transparency stays byte-identical
  (`StepColour.rgba(1.0, 0.5, 0.0, 1.0)` equals the existing golden). `scripts/interop/verify-export-alpha-edge-instance.sh`
  (with `--spike`) re-checks the exports with OCCT and FreeCAD.

=== Fixed

* `kstep import`: a product-structure chain of thousands of levels (a few hundred kilobytes) could exhaust OCCT's
  recursive transfer and crash the JVM; depth and cycles are now checked on the typed entities before the transfer and end
  in `limit_exceeded` (`KSTEP-I-010`). A length unit with conversion factor 0 no longer yields geometry of size 1e100.
* Documentation: ADR-0031, ADR-0032 and ADR-0030 no longer claim OCCT 7.8 compatibility or a Linux CI on 7.8; the
  Linux CI uses 7.9.2 and 7.8 is not tested.
* Export: a part colour together with a face colour no longer aborts with "unexpected entity OVER_RIDING_STYLED_ITEM ...
  refusing to merge it". The overriding item is merged fail-closed: simple instance with four arguments, attached to a
  face, overriding a styled item of the style closure through an acyclic chain of at most 16 that ends at a styled solid
  containing that face; unknown entities are still refused (ADR-0039 S2). Two single-style golden files guard the
  unchanged output.
* Import: the new colour and layer mode made the OCCT transfer quadratic in the number of layer assignments and distinct
  colours (80k layers took 41 s under the global OCCT lock). A pre-transfer typed count now rejects more than 4096 layer
  assignments or 10000 colour definitions with `limit_exceeded` (`KSTEP-I-010`). The count also covers
  `SURFACE_STYLE_TRANSPARENT` and `SURFACE_STYLE_RENDERING_WITH_PROPERTIES` (10000 each), because OCCT's colour table is keyed
  by RGBA and distinct colour x transparency pairs were still quadratic (80k styled items took 67 s). These caps bound
  only the size of the colour table, not the work, because every `STYLED_ITEM` scans that table once (a full table plus
  300k styled items took 116 s). The count therefore also covers `STYLED_ITEM` / `OVER_RIDING_STYLED_ITEM` (at most
  200000) and bounds styled items x (colour definitions + rendering records) to 100000000. The style lists of
  `PRESENTATION_STYLE_ASSIGNMENT`, `SURFACE_SIDE_STYLE` and `STYLED_ITEM` are walked once per styled item too and could
  repeat one reference cheaply (10k styled items x 200k entries took 53 s); lists longer than 64 entries are rejected.
* Import: capped style lists still multiplied, because the colour reader walks styled item -> presentation style
  assignment -> surface side style -> fill area style as nested loops (four lists of 64 = 16.7M steps per styled item;
  100 such items in a 71 kB file took 15 s). The pre-transfer check now sums the weighted expansion cost of all styled
  items (memoised per entity, linear in the file) and rejects more than 10000000 with `limit_exceeded` (`KSTEP-I-010`);
  real files cost 1-3 per styled item. The fill styles of `FILL_AREA_STYLE` and the properties of
  `SURFACE_STYLE_RENDERING_WITH_PROPERTIES` are capped at 64 as well. New constant
  `StepImportLimits.MAX_STYLE_EXPANSION_WORK`.
* Import: an assembly "diamond" (each level using the same sub-assembly twice) has a small depth but 2^levels
  occurrences, and OCCT expanded it during the transfer before the Kotlin occurrence limit fired (28 levels, 56 kB: 69 s).
  The pre-transfer structure check now also counts the part occurrences after expansion on the usage graph and rejects
  more than 10000 (`StepImportLimits.MAX_EXPANDED_OCCURRENCES`, now also checked natively) with `limit_exceeded`
  (`KSTEP-I-010`) in well under a second.
* `kstep import` runs the import in a worker subprocess (ADR-0038). Four audit rounds kept finding new loops inside OCCT
  (a self-overriding `OVER_RIDING_STYLED_ITEM`, deep override chains and `MAPPED_ITEM` chains or cycles ended the process
  with exit 132 and no output at all; override chains, `MAPPED_ITEM` diamonds and shells repeating one face ran into or
  past the 60 s bound). The command now starts a second JVM (same runtime and class path, `-Xmx2g`, no JVM crash banner)
  and only supervises it: a regular end (exit 0 or 1 with one complete report) is passed through unchanged; a timeout
  (60 s, can only be lowered via `-Dkstep.import.timeoutMillis` / `KSTEP_IMPORT_TIMEOUT_MILLIS`; the worker and its
  children are killed), an OutOfMemoryError or an output overflow become `limit_exceeded` (`KSTEP-I-010`), a crash or an
  incomplete report becomes `read_failed` (`KSTEP-I-009`), as text or `--output json`. With `--output json` stdout is
  always exactly one JSON document. The previous in-process watchdog (`Runtime.halt`) printed a JVM fatal-error banner on
  stdout when it ended a native call; it now only bounds an orphaned worker, silently. Cost: one extra JVM start per
  import (about 0.08 s, see ADR-0038). A 100000-deep override chain still crashes OCCT's reader before any pre-scan
  runs; it now ends as one `read_failed` document instead of a silent exit 132. Library callers of `StepImporter` / `OcctKernel.readStep` still run in-process without a time
  or memory bound, and `kstep-mcp` has no import tool.
* Import: three more pre-transfer checks give the known worst cases a structured error in under a second (the worker is
  the guarantee, these are the fast path): `OVER_RIDING_STYLED_ITEM` chains deeper than 16 or cyclic, `MAPPED_ITEM`
  nesting deeper than 32 or cyclic and more than 10000 mapped-item expansions, and more than 250000 face references
  summed over all shells are rejected with `limit_exceeded` (`KSTEP-I-010`). New constants
  `StepImportLimits.MAX_OVERRIDE_DEPTH` and `MAX_MAPPED_ITEM_EXPANSIONS`.
* Tests: a native handle-hygiene test compared the global shape counter exactly and failed once in a full build
  (the cleaner frees shapes of earlier tests asynchronously); it now allows a small growth. A test name was aligned
  with the CI skip guard's marker. The wall-clock bounds of the import limit tests were relaxed to 30 s for slower
  CI runners; the structured limit error is still asserted.

  occurrences and totals, as text or `--output json`; `--validate` checks the AP242 V1 entities, `--render
  <out.svg|png|glb>` renders the imported geometry. Read-only apart from `--render`. Kotlin API:
  `dev.kstep.shape.importer.StepImporter`/`ImportedStepModel`/`StepImportValidation`,
  `OcctKernel.readStep`/`OcctStepDocument`, `OcctShape.boundingBox`, `BoundingBox`, `Placement.fromRowMajor3x4`
  and `rowMajor3x4`, `StepImportLimits`, `OcctImportLimitException`, `MeshPreview` (the SVG/PNG/GLB encoders
  of `PreviewRenderer`, output unchanged). Input hardening: no symbolic links, regular files only, 50 MB cap,
  extern-document references rejected, entity/node/part/face/occurrence/depth limits. Error codes
  `KSTEP-I-001` to `KSTEP-I-012`. Linux CI that requires OCCT now installs `libocct-ocaf-dev`. New interop
  tools: `dump_xcaf_tree nested`, `freecad_make_box.py`, `verify-import.sh`.

* `kstep export` merges the geometry of `shape(...)` registrations into the exported Part 21 file
  (ADR-0027). `Ap242ShapeExporter.export(header, roots, assignments)` / `exportToFile` accept all
  roots and several shapes (one per product definition, limits `MAX_SHAPES` and
  `MAX_TOTAL_GEOMETRY_INSTANCES`); the single-assignment overload is unchanged in output.
* `kstep export --require-geometry`: exit 1 and no file unless geometry was merged.
* Error codes `KSTEP-S-006` (`GEOMETRY_REQUIRED`), `KSTEP-S-007` (`GEOMETRY_UNAVAILABLE`) and
  `KSTEP-S-008` (`GEOMETRY_EXPORT_FAILED`); `--output json` reports a `geometry` object when shapes
  are involved.

* Placed assembly geometry (ADR-0028, Welle I): `place(usage, translation, rotation)` in the script
  DSL with `vec(...)`, `Rotation.about(...)`, `Rotation.fromAxes(...)`; the exporter writes a
  `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION` chain per geometric usage, so OCCT and FreeCAD import the
  components of an assembly (previously only the root). `kstep export --output json` reports
  `geometry.placementCount`/`usageCount`. New interop tools `dump_xcaf_tree.cpp`,
  `freecad_assembly_check.py`, `verify-placed-assembly.sh`. Gate (2026-10-22, macOS arm64, OCCT 7.9.3):
  `clean check -Pkstep.occt.require=true -Pkstep.planegcs.require=true --no-build-cache`, 1277 tests,
  0 failures, 0 errors, 6 skipped (the six known ones).

* Geometry operations on the OCCT bridge (ADR-0029, Welle J): `OcctKernel.makeCylinder`,
  `translate`/`transformed`, `union`/`cut`/`common`/`boolean` (single-solid results, face-limited operands),
  `hole`, `revolveProfile` (about X or Y, `RevolveAxis`) and `chamfer`; `OcctEmptyResultException` for empty
  boolean results; feature-history cases `CylinderFeature`, `RevolveFeature`, `TranslateFeature`,
  `BooleanFeature`, `HoleFeature`, `ChamferFeature`; example scripts `hello-plate-with-hole`,
  `export-plate-with-hole`, `export-boolean-{union,common,cut}`, `export-revolved-sleeve`,
  `export-chamfered-prism`, `hello-revolve`; `scripts/interop/verify-geometry-operations.sh`. Gate
  (2026-10-22, macOS arm64, OCCT 7.9.3): `clean check -Pkstep.occt.require=true
  -Pkstep.planegcs.require=true --no-build-cache --rerun-tasks`, 1333 tests, 0 failures, 0 errors, 6 skipped
  (the six known ones). The six exported STEP files read back as valid solids in OCCT's typed reader and
  FreeCAD with the closed-form volumes.

=== Changed

* `OcctGeometryException` is now `open` (parent of `OcctEmptyResultException`); `FilletFeature` implements the
  new `DerivedFeature` interface (constructor and `copy` unchanged); the native bridge links `-lTKBO`.
* CI/release workflows: the `apt-get` steps first download (resumable, three attempts with per-attempt
  timeouts) and then install offline, with a 40-minute step limit, after a slow mirror held the Linux OCCT job
  up twice on 2026-10-22 (its dev packages pull in about 450 MB). The Linux OCCT job also caches the downloaded
  packages with `actions/cache` (one entry per ISO week).
* The MCP server now reports the project version to clients (read from the jar manifest); it reported a
  hard-coded `0.1.0`, including in the 0.1.1 release.
* Geometry exports with assembly usages now carry an identity placement for usages without
  `place(...)`; the export text line gains `and K placed usage(s)`. (Render, preview and GLB honour
  placements since ADR-0035.)
* `kstep export` no longer prints "geometry merging is not wired into 'export' yet". A merge failure
  (unreachable or duplicate product definition, closed shape, OCCT error) fails with exit 1 instead
  of writing a structure-only file; native shape handles are closed on every path.
* The OCCT bridge detaches OCCT's default message printers while writing STEP, so OCCT's
  "Statistics on Transfer" banners no longer pollute stdout (and `--output json`).

== 0.1.0 — 2026-10-19 (pre-release)

First tagged release. It is a *pre-release*: no artifacts are published (Maven Central, etc.), and
the native geometry bridges need system libraries (OpenCascade for the OCCT modules, Eigen headers
for PlaneGCS) and are only verified on Linux x86-64. CI runs on Linux only; the semantic core was
additionally built and tested locally on macOS (geometry tests skipped there). Build from source,
see link:docs/building.adoc[Building].

=== Semantic core (ISO 10303 AP242)

* EXPRESS parser (ANTLR4, `Express.g4`) and a semantic model with Kotlin code generation, verified
  against an excerpt of the real AP242 schema, now sixteen entities
  (`product_definition_occurrence` and the `name`/`description`/`id` attribute entities included).
* Code generation resolves transitive `TYPE` alias chains (cycle- and depth-guarded),
  `ENUMERATION OF (...)` as Kotlin enum classes and closed `SELECT` types as sealed interfaces
  (ADR-0020). `EXTENSIBLE` and `BASED_ON` types are rejected loudly. Only types reachable from the
  emitted entities are generated.
* `SUBTYPE OF` inheritance flattening; `kstep-core` is an ergonomic validating layer over the
  generated types (ADR-0004).
* `DERIVE` attributes as computed properties on generated types (ADR-0021); `get_name_value`,
  `get_description_value` and `get_id_value` intrinsics and the population derives (ADR-0023).
* `WHERE`-rule evaluation including `USEDIN`/`SIZEOF`, `INVERSE` evaluation over a
  reverse-reference index, `UNIQUE` rules `UR1`/`UR2` and the acyclic `WR1` check for assemblies,
  all with size and depth limits (ADR-0022, ADR-0023). Structured violations with stable
  `KSTEP-*` codes; `Ap242ModelValidator` for whole-model checks (opt-in, not yet part of
  `kstep export`).
* Mandatory-attribute presence enforcement (`KSTEP-M-001`, `KSTEP-M-002`).

=== STEP Part 21 and tooling

* STEP Part 21 writer and reader (`kstep-step21`), including tolerant reading and value grammar.
* `*.kstep.kts` scripting host and the `kstep export` CLI command.
* `kstep render` headless preview (SVG, PNG, text and self-contained glTF/GLB).
* `kstep asciidoc`: pre-processing of `kstep` blocks in AsciiDoc documents (ADR-0019).
* MCP server (`kstep mcp`) exposing the entity builders, Part 21 export and `validate_model` as
  LLM tools with structured validation feedback.

=== Geometry and viewer (native bridges; Linux x86-64 verified)

* OpenCascade JNI bridge: boxes, extrusion and fillet, AP242 shape assignment, parametric feature
  history (foundation), triangulation.
* PlaneGCS 2D constraint solver bridge: coincidence, distance, horizontal/vertical, point-on-line,
  parallel and perpendicular.
* Interactive Compose Desktop viewer: orbit, zoom, pan, multi-shape scenes, per-part colors and
  smooth per-vertex normals (ADR-0018).

=== Known limitations

* No published artifacts; build from source (JDK 21).
* Part 21 output is verified by self-round-trip only. Interoperability with external CAD/PLM tools
  (for example FreeCAD) has not been validated; a fixture for the manual check lives in
  `kstep-tests`. Update (0.1.1): FreeCAD 1.x reads the files without error (0 objects, no
  geometry is written) and an OpenCascade typed reader resolves the product structure; geometry
  and other tools remain unverified.
* `kstep export` and the script host do not run model-level validation yet; an assembly cycle
  is not detected on export (exit code 0). Update (0.1.1): `kstep export --validate` now
  does this opt-in; without the flag a cycle is still exported.
* `QUERY` and general EXPRESS functions are not evaluated; `INVERSE`/`USEDIN` roles over entities
  that are not modelled follow the assumptions documented in ADR-0022/0023.
* The AP242 schema is a vendored excerpt, not the full standard.
* The LLM benchmark is deferred to a later version.
