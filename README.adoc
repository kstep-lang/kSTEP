== Why kSTEP

LLMs are strong in popular, high-resource languages (Kotlin, Java, Python)
but measurably weak at generating external, low-resource DSLs — and STEP's
native exchange format (Part 21, graphs of `#123`-style entity references)
is a particularly hostile one to read or write directly.

kSTEP applies **Typed Domain Grounding (TDG)** — the pattern already
validated by its sibling project, https://github.com/kuml-dev/kUML[kUML]:
expose a domain as a type-safe, embedded Kotlin DSL with semantic
validation and structured errors, so that both human developers and LLM
agents can work in it reliably. The syntax stays Kotlin (high-resource);
only the vocabulary is domain-specific, enforced by the type system. A
strict type system, a compiler, and structured validation errors form a
feedback loop the LLM can act on directly, without a separate benchmark
or fine-tuning step. kSTEP compiles that DSL down to the neutral,
standardized ISO 10303 exchange format.

== Vision

kSTEP is not "just another CAD tool." The ambition is to cover the
**entire STEP standard (ISO 10303)**: CAD is the entry point, not the
boundary. STEP also spans manufacturing (STEP-NC), electrical and
electronics, kinematics, composites, FEM/simulation and plant/process data,
each carved out as its own Application Protocol (AP242, AP238, AP210, AP209,
and others). Those APs are the building blocks kSTEP intends to grow into.

It is the deliberate third way between classic, GUI-centric CAD suites and
niche code-first CAD: code-first, AI-first and STEP-native instead of
proprietary. It is the same thesis as its sibling project
https://github.com/kuml-dev/kUML[kUML] in the UML/SysML space, applied to the
engineering domain.

V1 deliberately starts narrow: a single Application Protocol (AP242), scoped
down to product structure and metadata (see
link:docs/roadmap.adoc[Roadmap] and kSTEP-ADR-0001). Geometry was added
afterwards as an optional layer.

== Status

The current release is **v0.3.0** (2026-10-24), a pre-release; changes on
the `master` branch after it are listed under "Unreleased" in the
link:CHANGELOG.adoc[CHANGELOG]. What is in place:

* EXPRESS parser, semantic model and Kotlin code generation, with an
  AP242 V1 entity layer (`kstep-core`) and STEP Part 21 export/import.
* A Kotlin scripting host for `*.kstep.kts` files, the `kstep` command-line
  tool (`export`, `import`, `render`, `asciidoc`, `mcp`) and an MCP server.
* Optional geometry: an OpenCascade (OCCT) bridge (primitives, booleans, holes,
  fillet/chamfer, mirror, uniform scale, shell, edge/face/vertex selection,
  persistent edge names, a feature history with undo/redo), a PlaneGCS sketch
  solver, placed assemblies, colours and layers in export and import, and
  headless preview rendering. Both native bridges need system libraries
  (Linux x86-64 or macOS arm64) and are not part of the release zip.

Pocket/hole from a face, draft and thickening are on the unreleased master (Welle Q2, ADR-0040).

Not yet available: PMI, names for the faces these create, Windows
and Intel Mac support for the native bridges, and interoperability checks
beyond OpenCascade-based readers (OCCT, FreeCAD).

The wave-by-wave log is in link:docs/status.adoc[Status]; open points are in
the link:docs/roadmap.adoc[Roadmap]. Both say what is and is not verified.

== Quickstart

Requires JDK 21. Build the command-line tool and export a product structure
to a STEP Part 21 file (the native geometry bridges are optional and not
needed for this):

[source,shell]
----
./gradlew clean :kstep-cli:installDist
----

Save this script as `bracket.kstep.kts`:

[source,kotlin]
----
val appCtx = applicationContext { application = "config control" }.getOrThrow()
val prodCtx = productContext {
    name = "engineering"; frameOfReference = appCtx; disciplineType = "mechanical"
}.getOrThrow()
val defCtx = productDefinitionContext {
    name = "engineering"; frameOfReference = appCtx; lifeCycleStage = "design"
}.getOrThrow()

val bracket = product("BRK-001") { name = "Bracket"; frameOfReference = setOf(prodCtx) }.getOrThrow()
val bracketFormation = productDefinitionFormation("BRK-001-F") { ofProduct = bracket }.getOrThrow()
val definition = productDefinition("BRK-001-D") {
    formation = bracketFormation
    frameOfReference = defCtx
}.getOrThrow()

stepFile(fileName = "bracket.step") {
    root(definition)
}
----

[source,shell]
----
kstep-cli/build/install/kstep-cli/bin/kstep-cli export bracket.kstep.kts
# Exported 1 root(s) to bracket.step
----

The installed launcher is named `kstep-cli`; the documentation calls the
command `kstep`. The same pipeline as a library, parsing an EXPRESS schema and
generating Kotlin source:

[source,kotlin]
----
import dev.kstep.express.codegen.ExpressKotlinCodeGenerator
import dev.kstep.express.semantic.ExpressSemanticModelBuilder

val schema = """
    SCHEMA example_schema;
      ENTITY product;
        id   : STRING;
        name : STRING;
      END_ENTITY;
    END_SCHEMA;
""".trimIndent()

val model = ExpressSemanticModelBuilder.build(schema)
println(
    ExpressKotlinCodeGenerator.generateFileSource(
        model.schemas.single(),
        "dev.kstep.generated.example",
    ),
)
// package dev.kstep.generated.example
//
// import kotlin.String
//
// public data class Product(
//   public val id: String,
//   public val name: String,
// )
----

More examples (validation, geometry, sketches, rendering, import) are in
link:docs/usage.adoc[Usage].

== Modules

[cols="1,3",options="header"]
|===
| Module | Purpose

| `kstep-core`
| Core DSL types, validation results and the generated AP242 V1 entity classes.

| `kstep-express`
| ANTLR4 EXPRESS parser, semantic model and Kotlin code generator.

| `kstep-step21`
| STEP Part 21 reader and writer for the AP242 entities.

| `kstep-script`
| Kotlin scripting host for `*.kstep.kts` scripts.

| `kstep-cli`
| Command-line entry point.

| `kstep-mcp`
| MCP server exposing the entity builders and Part 21 export as LLM tools.

| `kstep-geometry`
| Optional OpenCascade (OCCT) JNI bridge for B-Rep geometry.

| `kstep-constraints`
| Optional PlaneGCS bridge for 2D geometric constraints.

| `kstep-sketch`
| Constraint-sketch DSL.

| `kstep-shape`
| AP242 shape assignment: merges product structure with B-Rep solids.

| `kstep-render`
| Headless mesh projection and SVG/PNG/text/glTF rendering.

| `kstep-preview`
| Shared headless preview pipeline behind `render` and `asciidoc`.

| `kstep-docs:kstep-asciidoc`
| Asciidoctor pre-processing integration (`kstep asciidoc`).

| `kstep-viewer`
| Interactive OCCT shape viewer (Compose Desktop).

| `kstep-tests`
| Cross-module integration tests (Kotest).
|===

Details per module: link:docs/modules.adoc[Modules].
